# 闭包

## 核心回答（面试口述版，1 分钟能讲完）

闭包就是函数记住了定义时的词法作用域，即使它在外面跑，还能摸到当时那些变量。
形成要凑齐三件事：函数嵌套、内层用了外层的变量、内层函数被拿到外面去（返回、当回调、挂到对象上）。
常见用途：造私有变量、工厂函数、柯里化、防抖节流、一次绑定。
代价是外层变量的生命周期被拉长。大对象被闭包抓住，函数还活着，GC 收不走。
`var` 循环里绑事件会共用同一个 `i`，打出来全是最终值。改 `let`、再包一层函数、或 `bind` 都能修。

## 展开

1. 闭包形成的三个条件（缺一不可）

- 有内层函数（作用域嵌套）。
- 内层引用了外层的变量（形成自由变量）。
- 内层函数逃逸到外层作用域之外还被人握着，外层函数已经 return 了环境记录也不能拆。

少任何一条都只是普通作用域查找。函数里用自己的局部变量，那不叫闭包。

2. 闭包的内存泄漏问题 —— 什么情况会泄漏，怎么释放？

泄漏发生在：闭包函数长期活着（全局、事件监听、定时器、单例缓存），同时抓着用不到的大对象。
修法：用完把引用置 `null`；`removeEventListener` 要用同一个函数引用；`clearInterval`；只捕获需要的字段，别把整个 `this` 或巨大数组关进去。Chrome 里闭包引用的变量，V8 会做一些优化，但别指望它帮你把没用的大对象剪掉。

3. 闭包的常见应用场景（至少举 3 个）

- 模块私有状态：`const makeCounter = () => { let n = 0; return () => ++n }`。
- 防抖 / 节流：timer 存在闭包里。
- 柯里化、`once`、偏函数：记住已传入的参数。
- React 的函数组件每次 render 都是新闭包，这就是 hooks 依赖数组和「过期闭包」问题的来源。

## 代码 / 例子

```js
// var 循环：同一个 i，三个监听看到的都是 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var', i), 0);
}

// 修 1：let，每次迭代独立绑定
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log('let', i), 0);
}

// 修 2：IIFE 再包一层，把当时的 i 拷进参数
for (var i = 0; i < 3; i++) {
  ((j) => setTimeout(() => console.log('iife', j), 0))(i);
}

// 修 3：bind
for (var i = 0; i < 3; i++) {
  setTimeout(console.log.bind(null, 'bind', i), 0);
}
```

## 常见追问

- Q: 闭包和词法作用域的关系？
  A: 词法作用域是规则：标识符在哪声明就在哪找，跟谁调用无关。闭包是这条规则的结果：函数对象自带 `[[Environment]]`，指向定义时的词法环境。所以它被传到别处执行，查找仍然走那条链。没有词法作用域就谈不上闭包。

- Q: 为什么 setTimeout/setInterval 里常看到闭包？
  A: 定时器回调晚于当前函数返回。回调要读当时的变量，只能靠闭包。`setTimeout(fn, 0)` 本身不产生闭包，是你在 `fn` 里引用了外层变量才有。这也是 `var` 循环坑出现的地方：三个回调闭包盯着同一个 `i`。

## 自己的易错点 / 之前答崩过的地方

我以前把「函数套函数」直接叫闭包。内层没用外层变量，或没有逃逸，都不算。
循环坑我只会说「改 let」，说不清 let 是每次迭代新绑定。
还有把闭包当成一定会泄漏。泄漏看引用还在不在，不看有没有闭包。
