# 作用域与作用域链

## 核心回答（面试口述版，1 分钟能讲完）

作用域是变量能被访问到的范围，JS 用词法作用域：写代码的位置决定，不看运行时谁调用。
三层：全局、函数、块（`let` / `const` / `class`）。`var` 只有函数作用域，没有块。
查找变量从当前作用域往外走，一直到全局，找不到就 ReferenceError。
`var` 和 `function` 声明会提升，`var` 提升后是 `undefined`，函数声明整个体都上来。
`let` / `const` 也会提升，但进暂时性死区，声明前摸它就报错。
面试常考 `var a = b = 10`：`a` 是局部，`b` 没声明，偷偷挂到全局。

## 展开

1. 全局作用域 / 函数作用域 / 块级作用域（let/const）的区别

全局：浏览器是 `window` 上的属性（`var` 会挂，`let/const` 不挂 `window`）。脚本一加载就有，页面关掉才没。
函数：每次调用生成一个新的环境记录。`var`、`function`、函数参数都在这里。
块：`{}`、`if`、`for`、`switch`。只有 `let` / `const` / `class` 认块。`var` 写在 `if` 里照样漏到函数/全局。

2. 变量提升（Hoisting）的规则 —— var、function 声明、let/const 的不同表现

引擎先扫一遍声明再执行。
`var a = 1` 拆成：提升 `var a`（值是 undefined）+ 原位置赋值。
`function fn() {}` 整个函数提升，声明前就能调。同一个作用域里函数声明压过 var。
`let` / `const` 提升到块顶，但在真正执行到那一行前属于 TDZ。`const` 必须当场初始化。
函数表达式 `var fn = function(){}` 只提升变量名，调用时机跟 var 一样。

3. 作用域链查找的方向：从内到外，不是从外到内

当前环境记录 → 外层词法环境 → … → 全局。找到就停。
内层能看见外层，外层看不见内层。所以闭包能「记住」外层变量：内层函数的 `[[Environment]]` 一直指着那条链。

## 代码 / 例子

```js
function foo() {
  var a = b = 10;
  // 等价于：b = 10; var a = 10;
  // a 在 foo 里；b 没声明，非严格模式挂到全局
}
foo();
console.log(typeof a); // 'undefined'
console.log(b);        // 10

for (var i = 0; i < 3; i++) {}
console.log(i); // 3，var 漏出循环

for (let j = 0; j < 3; j++) {
  // 每次迭代一个新的 j 绑定，闭包能抓到当时那份
}
```

## 常见追问

- Q: 什么是暂时性死区（TDZ）？
  A: `let` / `const` 从进入块到执行完声明语句之前，这块区域叫 TDZ。这期间读、写、甚至 `typeof` 都会 `ReferenceError`。`typeof x` 对未声明变量是 `'undefined'`，对 TDZ 里的 `let x` 直接抛错。所以「声明前能不能碰」才是 let 和 var 的关键差别，不单是块不块。
