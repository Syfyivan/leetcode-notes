# 微任务与宏任务的执行顺序

## 核心回答（面试口述版，1 分钟能讲完）

先记住一条：当前调用栈清空后，先把微任务队列掏空，再取一个宏任务。
微任务里再注册微任务，还是这一轮清完。所以 `Promise.then` 套 `then` 会连着打完，才轮到 `setTimeout`。
浏览器微任务：`then/catch/finally`、`queueMicrotask`、`MutationObserver`。
浏览器宏任务：`setTimeout` / `setInterval`、事件、`postMessage`、`script`。
Node 多两个：`process.nextTick` 比 Promise 还急；`setImmediate` 在 check 阶段，和 `setTimeout` 谁先看当时在哪个阶段。
`async` 函数里 `await` 后面的代码就是微任务。输出题按「同步 → 微任务（含嵌套）→ 一个宏任务」往下推。

## 展开

1. 宏任务、微任务各有哪些成员（列表背下来）

微任务：
- `Promise.then` / `catch` / `finally`
- `queueMicrotask(fn)`
- `MutationObserver`
- Node：`process.nextTick`（单独一条队列，比上面更先）

宏任务：
- 整份 `<script>`
- `setTimeout` / `setInterval`
- I/O、UI 事件、`postMessage`、`MessageChannel`
- Node：`setImmediate`、部分 I/O 回调
- 渲染相关的 `requestAnimationFrame` 不算传统宏/微，挂在画帧前

2. 一个完整循环：调用栈清空 → 所有微任务跑完 → 渲染 → 取一个宏任务

同步代码（当前宏任务）跑完。
清微任务，包括执行过程中新塞进来的。
浏览器如果该画就 rAF + 样式 + 布局 + 绘制。
再取下一个宏任务，循环。Node 没有渲染，换成 libuv 六个阶段，每个阶段结束后先 nextTick 再 Promise。

3. 微任务里再注册微任务，会被当前轮次跑完吗？（会）

会。队列是「取完直到空」，不是「只跑登记时那一批」。所以 `then` 里再 `then` 仍然在 `setTimeout` 前面。死循环 `queueMicrotask` 会卡住渲染和宏任务，跟 `nextTick` 饿死 I/O 一个道理。

## 延伸

- 相关题：事件循环、async/await、手写 Promise 为什么 then 必须异步。
- 对比题：浏览器微任务清完再渲染；Node 每个阶段结束先 nextTick 再 Promise。
- 面试加码：输出题先标同步，再串微任务（含嵌套），最后 timeout。`async` 函数进门到第一个 await 是同步的。

## 代码 / 例子

```js
console.log('sync');

setTimeout(() => console.log('timeout'), 0);

queueMicrotask(() => console.log('micro'));

Promise.resolve().then(() => {
  console.log('then1');
  Promise.resolve().then(() => console.log('then2'));
});

(async () => {
  await null;
  console.log('await');
})();

// 浏览器：sync → micro → then1 → await → then2 → timeout
// await null 和 then 都是微任务，和登记顺序有关

// Node 再加：
process.nextTick(() => console.log('tick'));
setImmediate(() => console.log('immediate'));
// tick 在所有 Promise 微任务之前
```

## 常见追问

- Q: process.nextTick 和 Promise.then 在 Node 里谁更快？
  A: nextTick 更快。Node 每个阶段结束先清 nextTick 队列，再清 Promise 微任务。`nextTick` 里再套 `nextTick` 会把 I/O、timers 全部饿死，生产里别拿它当递归。需要「比 then 更早」才用，其余用 `queueMicrotask` 或 `then`。

## 自己的易错点 / 之前答崩过的地方

我以前以为微任务「本轮只跑现有的一批」，嵌套 then 被我排到 timeout 后面，输出题全错。
`setImmediate` 和 `setTimeout(fn,0)` 我背成固定顺序。主模块里两者是竞赛；在 I/O 回调里 immediate 才稳赢。
`async` 函数从第一行到第一个 await 是同步的，我把它整段标成微任务，前面的 `console.log` 位置就标错了。
