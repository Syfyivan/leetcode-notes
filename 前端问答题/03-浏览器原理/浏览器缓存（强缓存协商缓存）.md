# 浏览器缓存：强缓存 vs 协商缓存

## 核心回答（面试口述版，1 分钟能讲完）

浏览器先看强缓存，命中就直接用本地，连请求都不发（从内存或磁盘读，状态仍显示 200）。
强缓存看 `Cache-Control: max-age`，没有再看过时的 `Expires`。
没命中再走协商：带 `If-None-Match`（对 ETag）或 `If-Modified-Since`（对 Last-Modified）。服务器说没变就 304，省 body；变了就 200 带新内容。
ETag 比 Last-Modified 更准，精确到内容哈希，1 秒内改多次也能发现。
前端发版靠文件名带 hash：`app.a1b2.js`。入口 HTML 不缓存或缓存很短，旧 HTML 指向旧 hash，新 HTML 指向新文件。

## 展开

1. **强缓存**：Expires / Cache-Control（HTTP/1.1）——命中时完全不发请求
   - `Cache-Control: max-age / no-cache / no-store / public / private / must-revalidate` 各值含义

- `max-age=31536000`：从**响应时刻**起多少秒内有效，单位秒，优先于 Expires。
- `Expires`：HTTP/1.0 的绝对时间，受本地时钟影响。
- `no-cache`：可以存，但每次必须去服务器验证（走协商）。名字很误导。
- `no-store`：别存，敏感接口用。
- `public`：CDN / 共享缓存也能存。`private`：只允许浏览器存。
- `must-revalidate`：过期后必须再验证，不能直接用过期副本。
- `s-maxage`：给共享缓存（CDN）用，盖过 max-age。
- `immutable`：文件名带 hash 时告诉浏览器「这个 URL 内容不会变」，刷新也不重新验证。

2. **协商缓存**：ETag / If-None-Match（优先级高）+ Last-Modified / If-Modified-Since —— 发请求，命中返回 304

响应里带 `ETag: "abc"`，下次请求带 `If-None-Match: "abc"`。匹配就 304。
`Last-Modified` 是文件修改时间，下次带 `If-Modified-Since`。精度一般到秒。
两个都有时，规范让 ETag 说了算。304 响应几乎没有 body，浏览器沿用旧缓存并可以更新头。

3. 完整决策流程图：先查强缓存 → 命中直用；不命中 → 走协商缓存 → 304 / 200

```
请求资源
  ├─ 内存缓存？有 → 直接用
  ├─ 磁盘缓存且 max-age 没过？有 → 200 from disk
  └─ 带 If-None-Match / If-Modified-Since 发请求
        ├─ 304 → 用旧文件
        └─ 200 → 用新文件并写入缓存
```

`no-store` 这条路直接跳过存储。`no-cache` 跳过强缓存，每次都走协商。

4. 用户行为对缓存的影响：普通刷新 / 硬刷新（Cmd+Shift+R）/ 地址栏回车

- 地址栏回车 / 点链接：强缓存能命中就走强缓存。
- 普通刷新（F5）：浏览器对已打开的页面更倾向协商（`Cache-Control: max-age=0` 或带条件头），很多实现会跳过强缓存。
- 硬刷新（Ctrl+Shift+R / Cmd+Shift+R）：带 `Cache-Control: no-cache`，强制重新拉。
- 不同浏览器细节有差别，别把 F5 和「完全不用缓存」划等号。

## 常见追问

- Q: ETag 和 Last-Modified 各有什么优缺点？为什么有了 Last-Modified 还要 ETag？
  A: Last-Modified 便宜，文件系统自带 mtime。缺点：精度秒级，1 秒内改两次看不出来；CDN 拷文件可能改掉 mtime，内容没变也判成变了。ETag 按内容（或 inode+size+mtime）算，改一个字节就能发现。代价是服务器要算哈希，大文件弱 ETag（W/"..."）用启发式。两者一起用，内容哈希补时间戳的缝。

- Q: 前端资源更新时怎么让用户拿到新版本？（文件名 hash + 入口 HTML 不缓存或短缓存）
  A: webpack/vite 把内容 hash 打进文件名。内容变了 URL 变了，天然是新缓存键。HTML 作为入口设 `Cache-Control: no-cache` 或很短的 max-age，每次去服务器确认。HTML 里的 script/src 指向新 hash，旧文件可以继续被没刷新的用户用。CDN 上再配 `s-maxage` 给 HTML 短缓存、给 hashed 资源一年。

## 自己的易错点 / 之前答崩过的地方

我把 `no-cache` 说成「不缓存」。它是「能存但每次要验证」。真正不存是 `no-store`。
304 我以为浏览器会再下一次 body。304 没有 body，用的还是本地那份。
强缓存命中时 Network 面板写 200，我当成发了请求。要看 size 列的 `(memory cache)` / `(disk cache)`。
