# 贪心算法：写法简单，策略要命

> 这份笔记的核心：先想清楚两件事，**能不能贪** + **贪什么靶子**，再动手。
> 想清楚了，代码短到不真实（常是一次遍历 + 几个变量）；想错了，代码再对也是错的。
> 涉及题目：[买卖股票的最佳时机](../买卖股票的最佳时机.js)、[跳跃游戏](../跳跃游戏.js)、[跳跃游戏 II](../跳跃游戏%202.js)。

---

## 一、贪心 vs 动态规划：用 DP 当镜子

|            | 动态规划               | 贪心                                   |
| ---------- | ---------------------- | -------------------------------------- |
| 每步做选择 | 所有可能都算、都留着   | **当场拍板选一个，其它全扔**           |
| 会不会反悔 | 会（综合所有状态）     | **绝不回头**                           |
| 正确性     | 状态定义对就**一定对** | **可能错**：贪错靶子会静默算出错误答案 |
| 代价       | 空间/时间较大          | 极省，常 O(n) 一遍                     |

一句话心法：**DP 是"留着所有路慢慢挑"，贪心是"每步都赌当前最优，且赌对了永远不亏"。**

**和二分正好相反**：二分是想法简单、边界要命；贪心是**写法简单、策略要命**。

## 二、动手前的四个自问

```
1. 能不能贪？      → 局部最优能拼出全局最优吗？说服不了自己就退回 DP
2. 贪什么靶子？    → 每一步按什么规则选"当前最优"？（选错靶子 = 全盘错）
3. 凭什么不亏？    → 直觉验证：贪这一步会不会害我错过更好的全局
4. 落成代码        → 几乎都是"一次遍历 + 维护几个变量"
```

难度全在 1~3（脑子里），第 4 步手一抖就写完。

### 怎么嗅出"这可能是贪心"

- 问 **最大/最小/最多/最少**，且每步选择**相对独立**。
- **排序**之后问题就顺了（区间、分配类）。
- 感觉能 DP，但**数据量大到 DP 会超时**，逼你找 O(n) / O(n log n)。
- 信号只是"怀疑"，**确诊只有一招**：能不能说服自己"贪这一步永远不亏"。说不服 → 退回 DP。

## 三、两个高频骨架（贪心没有统一模板）

### 骨架 A：一次遍历 + 维护极值（不排序）

```javascript
let best = 初始值,
  状态 = 初始值;
for (const x of arr) {
  状态 = 更新(状态, x); // 贪心的更新规则
  best = Math.max(best, 用状态算出的候选);
}
return best;
```

本专题三题**全落在骨架 A**。

### 骨架 B：先排序 + 再线性扫描（区间/分配类）

```javascript
arr.sort((a, b) => a[某维] - b[某维]); // "按哪个维度排序" 本身就是贪心策略
for (const item of arr) {
  if (不冲突) {
    选它;
    更新状态;
  }
}
```

## 四、买卖股票的最佳时机（LC 121）：骨架 A 最纯的样子

只买卖一次，求最大利润。**两个 `Math` 各管一头，你一个决定都不用做**：

```javascript
var maxProfit = function (prices) {
  let best = 0;
  let minPrice = Infinity; // 用 Infinity 起手：空数组也不会算出 NaN
  for (const price of prices) {
    minPrice = Math.min(minPrice, price); // ① 买入日自动锁"迄今最便宜"
    best = Math.max(best, price - minPrice); // ② 每天都当卖出日试一遍
  }
  return best;
};
```

**关键领悟**：

- **"先小后大"是遍历方向白送的**：走到今天时，`minPrice` 里只可能是今天之前的价，不用判断。
- **不用挑哪天买卖**：卖出日每天都试（`Math.max`），买入日 `minPrice` 自动锁最便宜。
- **一个都不会落下**：`best` 用 `Math.max`，**只进不退**。旧机会在最低价被替换前，早已把利润存进 `best`；换最低价只影响"以后"，动不了已锁的战绩。
- **等价于 O(n²) 全枚举**：固定卖出日 j，最优买入日必是"j 之前最低价"，`minPrice` 直接给，省掉内层循环。

## 五、跳跃游戏（LC 55）：贪"能摸到的最远边界"

判断能否到达最后一个下标。

**⚠️ 靶子陷阱**：别贪"跳到跳跃力最大的格子"（错）。正确靶子是**"我脚力所及的最远边界 `max`"**。

```javascript
var canJump = function (nums) {
  let max = 0;
  const len = nums.length;
  for (let i = 0; i < len; i++) {
    if (max >= len - 1) return true; // 边界够到终点
    if (i <= max) {
      // 只有够得着的格子，才配更新 max
      max = Math.max(i + nums[i], max);
    }
  }
  return false; // 走完没够到 = 中途卡死（如 [3,2,1,0,4]）
};
```

- **`if (i <= max)` 是"够不着就判死"的逆否写法**：只让合法格子发言，死格（如那个 0）推不动 `max`，循环走完自然 return false。
- 能否到达**只取决于边界能否推到终点，与具体踩哪几格无关**。
- `max` 也是**只进不退**地记录"迄今最强脚力"（和股票的 `best` 同源）。

## 六、跳跃游戏 II（LC 45）：本专题最难，务必嚼透

求到达终点的**最少跳数**（题目保证一定能到）。在 55 的 `max` 之外，**再加一个 `curEnd`**。

```javascript
var jump = function (nums) {
  let max = 0; // farthest：当前层张望到的最远处（= 下一层右边界）
  let curEnd = 0; // 当前这一跳的射程边界（当前层右边界）
  let count = 0; // 跳数 = 层数
  const len = nums.length;

  for (let i = 0; i < len - 1; i++) {
    // ★ 到倒数第二格就停
    max = Math.max(max, i + nums[i]); // 逐格张望
    if (i === curEnd) {
      // 撞到当前射程尽头，被迫再跳一次
      count++;
      curEnd = max; // 新一跳延伸到 max
    }
  }
  return count;
};
```

### 心理模型：公交票 / BFS 分层

- **公交票**：手里一张票覆盖 `[起点..curEnd]`；坐车时一路张望沿途每格能延伸多远（`max`）；坐到票的终点 `curEnd` 还没到目的地 → 被迫**买下一张票（count++）**，新票延伸到 `max`。
- **BFS 分层**（和层序遍历同构）：每层 = 一张票的覆盖范围，`curEnd` = 当前层右边界，`max` = 下一层右边界，撞到 `curEnd` = 本层扫完进下一层。**跳数 = 层数**。

### 三个"想不到"的坑，逐个钉死

**坑 1：`count++` 挂在哪？**
❌ 挂 `i <= max`（每格都加）→ 数的是"走过几格"≈ len，不是跳数。
✅ 挂 `i === curEnd`（撞边界才加）→ 一整趟只发生几次，等于答案。**"撞边界"才代表上一跳射程用完、必须再跳。**

**坑 2：为什么循环到 `len - 1` 就停？**（最反直觉）
`count++` 记的是**"何时被迫决定下一跳"**，不是"何时落地"。用 `[2,3,1,1,4]`（终点下标4）验：

| i   | max | i===curEnd? | count    |
| --- | --- | ----------- | -------- |
| 0   | 2   | 0==0 →+1    | 1        |
| 1   | 4   | 1<2         | 1        |
| 2   | 4   | 2==2 →+1    | **2** ✅ |
| 3   | 4   | 3<4         | 2        |

若写成 `i < len`，会在 i=4（**已站在终点**）再撞一次 `curEnd`，count 白加成 3 ❌。
→ **终点是用来"到达"的，不是用来"起跳"的**，遍历不该把终点当起跳点。当 `curEnd` 已 ≥ 终点，最后一跳其实在更早撞边界时就记过账了。

**坑 3：为什么必须"逐格"张望，不能只看边界那格？**
下一跳能到多远，是当前层**每一格的落点共同决定的**，而最能蹦的格常**藏在层中间、不在边界**。反例 `[2,4,1,1,1,1,1]`：i=1 的 `1+4=5` 不是任何层的边界，却决定了第二层能到 5。少看它 → 边界算小 → 多跳一次。代价只是顺手多算一个 `Math.max`，仍是 O(n)。

**坑 4：45 里要不要像 55 那样判 `i <= max`？**
不用。题目保证能到 = **无死局**，可证 `i <= curEnd <= max` 恒成立，`i` 追不上边界，每格都够得着。加上也不错，只是永远为真、纯冗余。
→ 同一个 `max`：55 里是"生死线"（越过=死），45 里是"射程"（保证够得着，只管数跳数）。

### 备选：DP 版（O(n²)，想不通贪心时的退路）

和零钱兑换 `dp[i]`=凑金额 i 最少硬币数**完全同构**：

```javascript
const dp = new Array(len).fill(Infinity);
dp[0] = 0;
for (let i = 0; i < len; i++)
  for (let j = 1; j <= nums[i] && i + j < len; j++)
    dp[i + j] = Math.min(dp[i + j], dp[i] + 1);
return dp[len - 1];
```

`dp[i]` = 到下标 i 的最少跳数。数据量不大能过，代价是 O(n²)。

## 七、两个通用难点的破法（我的高频卡点）

### 难点 1：`Math.max` 还是 `Math.min`？擂台守擂

别背公式，把它想成打擂台：擂主在台上，挑战者 `x` 上来比一次，赢的留下当新擂主。`max` 留大的，`min` 留小的。

要做的**唯一决定**只有一个问句：

> **这个变量，值越大对我越有利，还是越小越有利？**

- 越大越有利 → `max`（利润、能跳多远、能覆盖到哪、能装多少）
- 越小越有利 → `min`（买入成本、最低价、最少步数）

对照本专题：股票 `minPrice` 越低越赚用 `min`；股票 `best` 越高越好用 `max`；跳跃 `max` 边界越远越好用 `max`。**先判"对我有利的方向"，用哪个 Math 自己就跳出来了。**

### 难点 2：边界（±1、循环到哪停）用手推最后一格

边界不靠背规律，用二分里练成的老招：**把边界那一格代进去手推一遍，看会不会多算或漏算。**

跳跃 II 的 `i < len` vs `len - 1` 就是这么推出来的：代入 i=4（终点那格），发现会多撞一次边界、count 白加 1，于是改成 `len - 1`。**遇到 ±1 犹豫，就手推临界那一格，别硬记。**

**为什么它难**：前几题的靶子顺着直觉能摸到；763 的靶子"每个字母最后出现的位置"藏得深，要**自己造一个量出来**（建模）。这类题靠**见识**（见过的套路数），不靠硬想。第一次见想不到很正常，把套路吃进肚子，下次同类就想得到。

**可迁移的套路（本题最大收获）**：

> 当"当前这一步的决定"依赖**后面才知道的信息**时，就**先扫一遍把那个信息全表存好**（预处理），第二遍再做决定。
> 两遍加起来仍是 O(n)，"贪心只能一遍"是错觉。

本题的"未来信息" = 每个字母最后出现的下标，用 `last` 表在第一遍存好。

**回来接着做时，先用大白话回答这三个问题（别写代码，先建画面）**：

1. 切到第一个 `a`（下标0）后想切一刀，能切吗？（`a` 后面还出现，切了它就被劈进两段，允许吗？）
2. 既然不能切，这一段**至少要拖到哪**才可能切？（拖到 `a` 最后一次出现之后）
3. 拖长途中遇到新字母 `b`，`b` 最后出现更靠后，段边界要不要跟着往后拖？（要，`b` 也不能被劈开）

回答完，"边界要一直往后拖到能盖住段内所有字母"这个画面就成立了，那时再自己翻成代码。**这道回来时不要看别人的代码骨架，照自己脑里的画面写。**

## 九、一句话总纲

- **难在动手前**：选对"贪什么靶子"、说服自己"不亏"；写法就 A/B 两个骨架。
- **`Math.max` / `Math.min` 的"只进不退"** 是贪心不丢机会的底层保证。
- **55 → 45 的升级**：从"一个 `max` 判可达" → "加 `curEnd`，撞边界才 +1 数跳数"。
- 想不通贪心的巧劲时，**老实写 DP 也能过**：先 AC，再回头啃贪心。
