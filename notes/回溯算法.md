# 回溯算法：一套骨架通吃

> 这份笔记记录的不是"每题一个模板"，而是**一副骨架 + 一把尺子**，用它去量任何一道回溯题该怎么填。
> 涉及题目：[子集](../子集.js)、[电话号码的字符组合](../电话号码的字符组合.js)、[组合总和](../组合总和.js)。

---

## 一、回溯的心脏：永远是这三行

不管什么题，`for` 循环里都是这三行，一字不差：

```javascript
path.push(选择);   // 选
dfs(下一步);        // 递归
path.pop();        // 撤销
```

**硬规则**：`push` 和 `pop` 必须成对，`pop` 必须在 `dfs` 返回后立即执行。这是"状态还原"，漏一个后面全错。

---

## 二、回溯家族地图

```
回溯 / DFS（都靠 push→dfs→pop 这副骨架）
│
├── A 类：收集「所有节点」
│     每走一步，当前 path 就是一个合法解 → 一进 dfs 就收，无需 return
│     代表：子集 / 幂集
│
└── B 类：收集「叶子节点」
      只有走到底（满足长度 / 填满 / 凑够）才算解 → 需要终止条件 + return
      │
      ├── 组合 (n选k)：同池子往后挑，start 传 i+1（每个数最多用一次）
      ├── 组合总和：同池子往后挑，start 传 i（同一个数可反复用）
      └── 电话号码：每层从各自不同的固定候选集挑一个，不用 start
```

**子集在 A 类，电话号码 / 组合总和在 B 类。** 它们是不同子类型，但共用同一副骨架。

---

## 三、三要素：量任何回溯题的尺子

遇到新题，只问这三个问题：

| 三要素 | 子集（A类） | 电话号码（B类） | 组合总和（B类） |
|---|---|---|---|
| **① 每步的选择** | 从 `start` 往后挑一个数 | 当前这位数字对应的字母挑一个 | 从 `start` 往后挑一个数（额度够才挑） |
| **② 收集时机** | 一进来就收（每个节点都算） | 填满才收（`index === len`） | 凑够才收（`sum === target`） |
| **③ 约束 / 防重** | `start` 传 `i+1` 防同池重复 | 不用防重（每层候选集本就不同） | `start` 传 `i`（可复选）+ `sum > target` 剪枝 |

## 四、用"画面"理解三道题（比术语好记）

### 子集 `nums = [1,2,3]`
一排数从左往右走，**边走边捡**，每停一下手里那串都算答案。怕 `[1,2]` 和 `[2,1]` 重复，所以用 `start` 逼你"只准往后拿"。

### 电话号码 `digits = "23"`
桌上两个空格子，格子1只能填 `abc`、格子2只能填 `def`，**填满两格才交卷**。两个格子候选不重叠，所以**不用防重**。本质是笛卡尔积 `abc × def`。

### 组合总和 `candidates=[2,3,6,7], target=7`
手里一个篮子 + 一个剩余额度。每步挑一个数放进篮子、额度减掉它，**额度正好为 0 才收**，超了就剪掉。传 `i`（不是 `i+1`）让同一个数能反复选。

## 五、为什么 return 是必须的？（B 类的关键）

**`return` 不是为"收集"服务的，是为"别执行后面那段会越界 / 会超的探索"服务的。**

- **子集不需要 return**：收集点后面跟着 `for(i=start; i<n)`，到叶子时 `start` 越界，`for` 一次都不进，**自带刹车**。
- **电话号码需要 return**：收集后面跟着 `map[digits[index]]`，`index` 到头时 `digits[index]` 越界成 `undefined`，`for...of undefined` 直接崩，**必须亲手刹车**。
- **组合总和需要两个 return**：`sum === target` 收集后 return；`sum > target` 剪枝 return（否则 `dfs(i)` 可复选会无限累加爆栈）。

> 剪枝放 `for` **外面**（函数开头当出口）比放 `for` 里面省心——进门先判断，此时还没 push、没改任何状态，`return` 掉头干干净净，不用撤销。

## 六、状态传递：闭包 vs 参数（最容易踩坑的地方）

这是回溯里所有状态（`sum`、`path`、`curStr`…）通用的一条分水岭：

| 状态类型 | 闭包式（改 + 撤） | 参数式（送新值、免撤） |
|---|---|---|
| `sum`（数字） | `sum += x` … `sum -= x` | `dfs(i, sum + x)` |
| `path`（数组） | `path.push(x)` … `path.pop()` | `dfs(i, [...path, x])`（每层造新数组）|
| `curStr`（字符串） | 外部拼接 + slice 撤 | `dfs(curStr + ch, i+1)` |

### 一句话铁律
> **要么"自己改、自己撤"（闭包），要么"不碰自己、只送新值"（参数）。选了参数就是为了免撤销，那就绝不能再手动改。**

### 经典 bug：混用
```javascript
sum += candidates[i];   // 闭包式：改了本层的 sum 储物格
dfs(i, sum);            // 参数式：又把它当参数传
path.pop();             // 只撤了 path，没撤 sum！
```
`sum += x`（改自己的储物格）和 `sum + x`（送出一个新值）是两回事。for 循环的每个兄弟分支都要读本层那个 `sum` 储物格，所以只能"送新值"，不能"改储物格"——除非改完立刻 `-=` 擦干净。

### 实战最优搭配
- **`path` 用闭包 + push/pop**：省得每层复制整个数组（`[...path]` 是 O(n)）。
- **`sum` 用参数传值**：数字复制是 O(1)、几乎免费，还省了撤销。

## 七、底层机制：栈为什么能"保存"和"回退"？

把"调用栈"想成**一摞盘子**。每次 `dfs(...)` 就造一个新盘子放最上面，盘子上放着**这一层专属**的参数、局部变量 `i`，和一个"我从上层哪一行来的"书签。

- **保存**：下层盘子压上来时，**碰不到下面盘子里的东西**。所以上层的 `sum`、`i` 原封不动地躺着——不是谁主动去存，是天然被压在下面动不了。
- **回退**：上层盘子执行完被扔掉，露出下面的盘子，照着书签回到"调用的下一行"继续。下层的值从头到尾没被动过，扔掉上层自然就露出原值。

### 闭包和栈的关系
- **参数**（`sum`、`i`、`start`）住在**盘子里** → 栈自动保存 / 回退，**你啥都不用做**。
- **闭包变量**（`path`、外部 `sum`）住在**所有盘子外面的大房间里**，全程只有一份 → 栈管不着，**你必须手动 `push/pop`、`+=/-=`** 去模拟栈本来会做的还原。

> 一句话：**栈只会自动照顾"盘子里的"，照顾不到"盘子外的"。** 参数在盘子里（免撤销），闭包在盘子外（必须手动撤销）。混用出错，就是把一个盘子外的东西当盘子里的用了。

## 八、学习策略（给未来的自己）

- 新类型题：坚持**画全决策树**建立模型；熟练后转为只思考"三要素"，不再脑内模拟递归。
- 关注**本层责任**（这一步选什么、要不要收、要不要撤），把执行过程交给栈。
- 记住画面（一排数捡 / 填格子 / 篮子凑数），术语只是画面的标签。
