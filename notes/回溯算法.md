# 回溯算法：一套骨架通吃

> 这份笔记记录的不是"每题一个模板"，而是**一副骨架 + 一把尺子**，用它去量任何一道回溯题该怎么填。
> 涉及题目：[子集](../子集.js)、[电话号码的字符组合](../电话号码的字符组合.js)、[组合总和](../组合总和.js)、[括号生成](../括号生成.js)。

---

## 一、回溯的心脏：永远是这三行

不管什么题，`for` 循环里都是这三行，一字不差：

```javascript
path.push(选择); // 选
dfs(下一步); // 递归
path.pop(); // 撤销
```

**硬规则**：`push` 和 `pop` 必须成对，`pop` 必须在 `dfs` 返回后立即执行。这是"状态还原"，漏一个后面全错。

---

## 二、回溯家族地图

```
回溯 / DFS（都靠 push→dfs→pop 这副骨架）
│
├── A 类：收集「所有节点」
│     每走一步，当前 path 就是一个合法解 → 一进 dfs 就收，无需 return
│     代表：子集 / 幂集
│
└── B 类：收集「叶子节点」
      只有走到底（满足长度 / 填满 / 凑够）才算解 → 需要终止条件 + return
      │
      ├── 组合 (n选k)：同池子往后挑，start 传 i+1（每个数最多用一次）
      ├── 组合总和：同池子往后挑，start 传 i（同一个数可反复用）
      ├── 电话号码：每层从各自不同的固定候选集挑一个，不用 start（for 遍历候选）
      └── 括号生成：每层就"放左 / 放右"两个固定选择，用两个平行 if（不是 for）
```

**子集在 A 类，电话号码 / 组合总和在 B 类。** 它们是不同子类型，但共用同一副骨架。

---

## 三、三要素：量任何回溯题的尺子

遇到新题，只问这三个问题：

| 三要素            | 子集（A类）                 | 电话号码（B类）                | 组合总和（B类）                               |
| ----------------- | --------------------------- | ------------------------------ | --------------------------------------------- |
| **① 每步的选择**  | 从 `start` 往后挑一个数     | 当前这位数字对应的字母挑一个   | 从 `start` 往后挑一个数（额度够才挑）         |
| **② 收集时机**    | 一进来就收（每个节点都算）  | 填满才收（`index === len`）    | 凑够才收（`sum === target`）                  |
| **③ 约束 / 防重** | `start` 传 `i+1` 防同池重复 | 不用防重（每层候选集本就不同） | `start` 传 `i`（可复选）+ `sum > target` 剪枝 |

## 四、用"画面"理解三道题（比术语好记）

### 子集 `nums = [1,2,3]`

一排数从左往右走，**边走边捡**，每停一下手里那串都算答案。怕 `[1,2]` 和 `[2,1]` 重复，所以用 `start` 逼你"只准往后拿"。

### 电话号码 `digits = "23"`

桌上两个空格子，格子1只能填 `abc`、格子2只能填 `def`，**填满两格才交卷**。两个格子候选不重叠，所以**不用防重**。本质是笛卡尔积 `abc × def`。

### 组合总和 `candidates=[2,3,6,7], target=7`

手里一个篮子 + 一个剩余额度。每步挑一个数放进篮子、额度减掉它，**额度正好为 0 才收**，超了就剪掉。传 `i`（不是 `i+1`）让同一个数能反复选。

### 括号生成 `n = 3`

一步步往字符串里放括号，每步只有两个选择：放 `(` 或放 `)`。**左右各放满 n 个才交卷**。约束靠两个门卫：放左要 `left < n`，放右要 `right < left`（右不能比左多，否则出现不合法的 `)`）。

## 五、为什么 return 是必须的？（B 类的关键）

**`return` 不是为"收集"服务的，是为"别执行后面那段会越界 / 会超的探索"服务的。**

- **子集不需要 return**：收集点后面跟着 `for(i=start; i<n)`，到叶子时 `start` 越界，`for` 一次都不进，**自带刹车**。
- **电话号码需要 return**：收集后面跟着 `map[digits[index]]`，`index` 到头时 `digits[index]` 越界成 `undefined`，`for...of undefined` 直接崩，**必须亲手刹车**。
- **组合总和需要两个 return**：`sum === target` 收集后 return；`sum > target` 剪枝 return（否则 `dfs(i)` 可复选会无限累加爆栈）。

> 剪枝放 `for` **外面**（函数开头当出口）比放 `for` 里面省心——进门先判断，此时还没 push、没改任何状态，`return` 掉头干干净净，不用撤销。

## 六、状态传递：闭包 vs 参数（最容易踩坑的地方）

这是回溯里所有状态（`sum`、`path`、`curStr`…）通用的一条分水岭：

| 状态类型           | 闭包式（改 + 撤）             | 参数式（送新值、免撤）                 |
| ------------------ | ----------------------------- | -------------------------------------- |
| `sum`（数字）      | `sum += x` … `sum -= x`       | `dfs(i, sum + x)`                      |
| `path`（数组）     | `path.push(x)` … `path.pop()` | `dfs(i, [...path, x])`（每层造新数组） |
| `curStr`（字符串） | 外部拼接 + slice 撤           | `dfs(curStr + ch, i+1)`                |

### 一句话铁律

> **要么"自己改、自己撤"（闭包），要么"不碰自己、只送新值"（参数）。选了参数就是为了免撤销，那就绝不能再手动改。**

### 经典 bug：混用

```javascript
sum += candidates[i]; // 闭包式：改了本层的 sum 储物格
dfs(i, sum); // 参数式：又把它当参数传
path.pop(); // 只撤了 path，没撤 sum！
```

`sum += x`（改自己的储物格）和 `sum + x`（送出一个新值）是两回事。for 循环的每个兄弟分支都要读本层那个 `sum` 储物格，所以只能"送新值"，不能"改储物格"——除非改完立刻 `-=` 擦干净。

### 实战最优搭配

- **`path` 用闭包 + push/pop**：省得每层复制整个数组（`[...path]` 是 O(n)）。
- **`sum` 用参数传值**：数字复制是 O(1)、几乎免费，还省了撤销。

## 七、底层机制：栈为什么能"保存"和"回退"？

把"调用栈"想成**一摞盘子**。每次 `dfs(...)` 就造一个新盘子放最上面，盘子上放着**这一层专属**的参数、局部变量 `i`，和一个"我从上层哪一行来的"书签。

- **保存**：下层盘子压上来时，**碰不到下面盘子里的东西**。所以上层的 `sum`、`i` 原封不动地躺着——不是谁主动去存，是天然被压在下面动不了。
- **回退**：上层盘子执行完被扔掉，露出下面的盘子，照着书签回到"调用的下一行"继续。下层的值从头到尾没被动过，扔掉上层自然就露出原值。

### 闭包和栈的关系

- **参数**（`sum`、`i`、`start`）住在**盘子里** → 栈自动保存 / 回退，**你啥都不用做**。
- **闭包变量**（`path`、外部 `sum`）住在**所有盘子外面的大房间里**，全程只有一份 → 栈管不着，**你必须手动 `push/pop`、`+=/-=`** 去模拟栈本来会做的还原。

> 一句话：**栈只会自动照顾"盘子里的"，照顾不到"盘子外的"。** 参数在盘子里（免撤销），闭包在盘子外（必须手动撤销）。混用出错，就是把一个盘子外的东西当盘子里的用了。

### 更精确：盘子（栈）里放的不是数组本身，是"便利贴"

- **数字**（`i`、`sum`）小，**本体直接住在盘子里**。每层一份，互不干扰，栈自动存/回退。
- **数组 / 对象**（`path`）大，本体放在**桌上（堆 heap），全程只有一份**；盘子里只放一张**指向它的便利贴（引用/地址）**。所有层的便利贴都指向桌上**同一个** `path`。
  - 所以你 `path.push(x)` 改的是桌上那个数组，**每一层看到的都跟着变**（因为是同一个）。
  - 扔盘子只扔盘子（连同便利贴），**碰不到桌上的数组**，所以 `path` 不会自动回退 → **必须手动 `pop`**。
- 推论：**数组当参数传，传的也只是便利贴**。想真正给下层一份独立副本，得 `[...path]` 才是"复制一个新数组放到桌上"。

> 数字 vs 数组的差别，就是"本体住盘子里" vs "本体住桌上、盘子里只有便利贴"。这解释了为什么 `sum` 传参免撤销、而 `path` 共享必须手动 pop。

### pop 不是紧跟 push 执行的——它被 dfs "挡住"了

理解回溯执行最难的一步：`push → dfs → pop` 三行里，**`pop` 要等中间那个 `dfs`（下一层的全部过程）跑完才轮到执行**。所以"上层放的东西，在下层期间一直留在 `path` 里"。

以 `n=1`（括号生成）完整走一遍，盯着 `path` 看：

```
【第0层】dfs(0,0)  path=[]
  放左 push '(' → path=['(']
  dfs(1,0) ↓ 进第1层（左括号没 pop，还在！）
  │  【第1层】dfs(1,0)  path=['(']
  │    放右 push ')' → path=['(', ')']   ← 上层的 ( 还在，所以这里凑成两个！
  │    dfs(1,1) ↓ 进第2层
  │    │  【第2层】dfs(1,1)  right===n 满足
  │    │    res.push(path.join(''))  📸 把 "()" 拍照存进 res → return
  │    pop ')' → path=['(']
  │  （第1层结束返回）
  pop '(' → path=[]    ← 第0层的 pop 现在才执行
（结束）

path 最终 = []（空）   res 最终 = ["()"]（照片还在！）
```

### 顿悟：path 归零 ≠ res 归零

- **path 是"正在走的路"**：一路 push/pop，递归结束时被擦得干干净净、归零。
- **res 是"沿途拍的照片集"**：`path.join('')`（或 `[...path]`）在收集那一刻**拷贝出一个全新独立的值**存进 res，从此和 path 再无关系。后面 path 怎么 pop 都碰不到它。

> 这就是硬规则"收集必须用快照"的意义：**脚印（path）会全部消失，但照片（res）一张不少。** `res.push(path.join(''))` = 拍照存档，被拍的人（path）之后怎么变，照片都不变。

### 附带教训：验证靠运行，不靠脑补

写完直接跑（`node -e "..."` 打印几个用例），别在脑子里推断对错。人（包括很有经验的人）脑内推演极易误判——本题作者一度误以为 `right === n` 不够、需要 `left===n && right===n`，实跑才发现：因为门卫 `right < left` 保证了 `right ≤ left ≤ n`，`right` 到 `n` 时 `left` 必然也到 `n`，所以 `right === n` 单独判断完全正确且更简洁。

## 八、什么时候用 for，什么时候用平行 if？

分叉的产生有两种形式，判断标准**不是"选项几个"，而是"候选从哪来"**：

| 问自己       | 用 `for`                        | 用平行 `if` 分支           |
| ------------ | ------------------------------- | -------------------------- |
| 候选是什么   | 一个数组/字符串（**数据结构**） | 几个写死的动作（**代码**） |
| 数量何时确定 | **运行时**才知道，且可能变      | **写代码时**就定死         |
| 每个候选逻辑 | **相同**（统一 push→dfs→pop）   | **不同**（各有各的门槛）   |
| 例子         | 子集、组合总和、电话号码        | 括号生成（放左 / 放右）    |

- **`for`**：像去水果店，老板递你**一袋水果**（`letters`、`candidates`），你不知道袋里几个，只能一个一个掏。哪怕这次恰好只有 1 个，也照样用 for——因为你写代码时不知道会是几个。**"选项只有 1 个"不是不用 for 的理由。**
- **平行 `if`**：像面前**两个写死的按钮**（左/右），你明确知道就这俩，而且每个按钮亮不亮的条件还不同，就分别判断。

> 括号题硬用 `for (const ch of ['(', ')'])` 也能写，但要在循环体里再用 `if (ch === '(')` 把左右拆开——**先合并再拆开，白绕一圈**。这反证了：候选规则不同时，for 帮倒忙，直接写平行 if 才"形状匹配"。

## 九、分叉 = 平行 if（不是 if...else！）

回溯里"这一步能放左、也能放右"这种分叉，**千万别用 `if...else`**：

```javascript
// ❌ 错：else 让它变成"二选一"，放了左就不放右了
if (能放左) {
  放左;
} else if (能放右) {
  放右;
}

// ✅ 对：两个独立平行的 if，两条路都要试
if (left < n) {
  path.push("(");
  dfs(left + 1, right);
  path.pop();
}
if (right < left) {
  path.push(")");
  dfs(left, right + 1);
  path.pop();
}
```

**为什么平行 if 就实现了分叉？** 第一个 if 里的 `dfs` 会**完整跑完整棵子树、返回、pop**，接着才轮到第二个 if。于是同一个节点先把"左"这条路走到底、回来，再走"右"——这就是一个节点长出两个孩子。

> **口诀：`for` 的每一圈、每一个平行 `if`，都是"长出一个孩子"。要几条分叉就写几个平行 if（或 for 转几圈），绝不能用 else 串成二选一。**

### 门卫心法（本轮最大收获）

**回溯不是"判断现在该做什么"，而是"给每个选择配一个门卫（准入条件），把所有选择都摆出来，让门卫自动放行或拦截"。**

- "只能放左"：门卫A（`left<n`）放行，门卫B（`right<left`）拦住 → 只走左。
- "只能放右"：门卫A 拦住，门卫B 放行 → 只走右。
- "左右都能放"：两个门卫都放行 → 两条都走。

**你根本不用去想"当前处于哪种局面"**——局面是所有门卫的放行结果**自动拼出来的**。你只负责给每个选择单独定一条"什么条件下允许"的规则。这跟人脑"先列举所有情况再决策"的本能相反，所以很难想到，但这正是回溯的精髓。

## 十、写递归时，不要在脑子里追踪执行！

**"不敢写递归"的根源，往往是误以为"写之前必须能在脑内把 push/dfs/pop 跑一遍"——这个前提是错的，人脑几乎做不到，也不需要。**

写递归 ≠ 追踪递归执行，这是两件事：

|            | 写递归           | 追踪执行           |
| ---------- | ---------------- | ------------------ |
| 要懂堆栈吗 | **不需要**       | 需要               |
| 难度       | 简单（只想一层） | 极难（人脑容易乱） |
| 何时用     | **写代码时**     | 调试 / 建立直觉时  |

### 写代码只靠"单层契约"——回答三个问题就够

想象自己只是"某一层"的员工，看不到上层也看不到下层，只回答：

1. **什么时候交货？**（收集 / 终止）→ 括号：`left===n && right===n`
2. **我这层有哪些选择？每个的门槛是什么？**（几个选择就几个平行 if / 或一个 for）→ 放左 `left<n`、放右 `right<left`
3. **每个选择怎么"选→交给下层→撤销"？**→ `push → dfs → pop`

回答完，代码就写完了。**全程不需要在脑子里跑任何 push/pop 顺序**——那是机器（栈）的活。

> **递归的美妙之处，恰恰是"你不需要理解它怎么执行，也能写对它"。** 你负责写好"一层的规矩"，机器负责把这层规矩在成千上万层里精确地叠起来、拆下来。越不去追踪它，越写得对。

### 治"不敢写"的练习法

强制自己**不许脑内模拟执行**，只做三步：写终止 → 写每个选择的门槛 → 每个填 push/dfs/pop。写完**别脑内验证，直接跑代码**，用运行结果代替脑内模拟。

## 十一、学习策略（给未来的自己）

- 新类型题：坚持**画全决策树**建立模型；熟练后转为只思考"三要素"，不再脑内模拟递归。
- 关注**本层责任**（这一步选什么、要不要收、要不要撤），把执行过程交给栈。
- 记住画面（一排数捡 / 填格子 / 篮子凑数），术语只是画面的标签。
