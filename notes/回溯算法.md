# 回溯算法

> 这份笔记想记的是一套通用思路，不是每题背一个模板。核心就两样东西：一个固定的代码骨架，加上几个"该怎么填"的判断问题。
> 涉及题目：[子集](../子集.js)、[电话号码的字符组合](../电话号码的字符组合.js)、[组合总和](../组合总和.js)、[括号生成](../括号生成.js)、[单词搜索](../单词搜索.js)、[分割回文串](../分割回文串.js)。

---

## 一、骨架：核心就这三行

大部分回溯题，`for` 循环里都是这三行：

```javascript
path.push(选择); // 选
dfs(下一步); // 递归
path.pop(); // 撤销
```

`push` 和 `pop` 要成对，`pop` 放在 `dfs` 返回之后。这一步是状态还原，漏了后面全错。

---

## 二、回溯家族地图

```
回溯 / DFS（都靠 push→dfs→pop 这副骨架）
│
├── A 类：收集「所有节点」
│     每走一步，当前 path 就是一个合法解 → 一进 dfs 就收，无需 return
│     代表：子集 / 幂集
│
└── B 类：收集「叶子节点」
      只有走到底（满足长度 / 填满 / 凑够）才算解 → 需要终止条件 + return
      │
      ├── 组合 (n选k)：同池子往后挑，start 传 i+1（每个数最多用一次）
      ├── 组合总和：同池子往后挑，start 传 i（同一个数可反复用）
      ├── 电话号码：每层从各自不同的固定候选集挑一个，不用 start（for 遍历候选）
      └── 括号生成：每层就"放左 / 放右"两个固定选择，用两个平行 if（不是 for）

└── C 类：网格搜索（在二维矩阵里找路径 / 连通块）
      四方向扩散，走过的格子直接在原数据上"盖章"防重踩，不外挂 path
      带返回值：找到就一路 return true 抬回顶层
      代表：单词搜索 / 岛屿数量 / 被围绕的区域
```

子集在 A 类，电话号码 / 组合总和 / 括号生成在 B 类，单词搜索在 C 类。子类型不同，骨架是同一套。

## 三、三要素：判断一道回溯题怎么填

遇到新题，先问这三个问题：

| 三要素            | 子集（A类）                 | 电话号码（B类）                | 组合总和（B类）                               |
| ----------------- | --------------------------- | ------------------------------ | --------------------------------------------- |
| **① 每步的选择**  | 从 `start` 往后挑一个数     | 当前这位数字对应的字母挑一个   | 从 `start` 往后挑一个数（额度够才挑）         |
| **② 收集时机**    | 一进来就收（每个节点都算）  | 填满才收（`index === len`）    | 凑够才收（`sum === target`）                  |
| **③ 约束 / 防重** | `start` 传 `i+1` 防同池重复 | 不用防重（每层候选集本就不同） | `start` 传 `i`（可复选）+ `sum > target` 剪枝 |

## 四、用"画面"理解三道题

### 子集 `nums = [1,2,3]`

一排数从左往右走，边走边捡，每停一下手里那串都算答案。怕 `[1,2]` 和 `[2,1]` 重复，所以用 `start` 逼着只往后拿。

### 电话号码 `digits = "23"`

桌上两个空格子，格子1只能填 `abc`、格子2只能填 `def`，填满两格才交卷。两个格子候选不重叠，不用防重。本质是笛卡尔积 `abc × def`。

### 组合总和 `candidates=[2,3,6,7], target=7`

手里一个篮子加一个剩余额度。每步挑一个数放进篮子、额度减掉它，额度正好为 0 才收，超了就剪掉。传 `i`（不是 `i+1`）让同一个数能反复选。

### 括号生成 `n = 3`

一步步往字符串里放括号，每步只有两个选择：放 `(` 或放 `)`，左右各放满 n 个才交卷。约束靠两个门卫：放左要 `left < n`，放右要 `right < left`（右不能比左多，否则出现不合法的 `)`）。

## 五、为什么 return 是必须的（B 类的关键）

return 的作用不是收集，是拦住收集点后面那段探索。那段代码继续跑会越界，或让 sum 超标。

- **子集不需要 return**：收集点后面跟着 `for(i=start; i<n)`，到叶子时 `start` 越界，`for` 一次都不进，自带刹车。
- **电话号码需要 return**：收集后面跟着 `map[digits[index]]`，`index` 到头时 `digits[index]` 变 `undefined`，`for...of undefined` 直接崩，得亲手刹车。
- **组合总和需要两个 return**：`sum === target` 收集后 return；`sum > target` 剪枝 return（否则 `dfs(i)` 可复选会无限累加爆栈）。

剪枝放 `for` 外面（函数开头当出口）比放里面省心：进门先判断，此时还没 push、没改状态，`return` 掉头就走，不用撤销。

### 看不出退出条件怎么办：三步定位法

想不到 dfs 的退出条件，是回溯里最卡人的一步。它有个固定找法：

> 递归每往下一层，总有个量在推进或减少。这个量推到头，就是退出条件。

别去想"整个过程怎么结束"（那是脑内追踪执行，人做不到），只问三步：

1. **进度条是谁**：每层递归传下去、在变的那个量。
2. **它推到头是什么样**：那就是终点。
3. **终点处干嘛**：收集 `res.push([...path])` 然后 `return`。

对照做过的题，退出条件都是"某个推进量到达终点"：

| 题目       | 进度条（每层推进啥）  | 推到头 = 退出条件            |
| ---------- | --------------------- | ---------------------------- |
| 子集       | `start` 往后挪        | `start` 越界（for 隐式退出） |
| 电话号码   | `index` 第几位数字    | `index === len`（填满）      |
| 组合总和   | `sum` 累加            | `sum === target`（凑够）     |
| 括号生成   | 已放括号数            | `left===n && right===n`      |
| 分割回文串 | 剩余串 `str` 越切越短 | `str === ''`（切光）         |
| 单词搜索   | `index` 匹配到第几位  | `index === word.length-1`    |

写 dfs 时先写退出、再写循环：第一行先留退出位（`if (进度到头) { 收集; return; }`），再写下面的选择循环。把找退出条件当成动手前的第一步，就不容易漏。

## 五点五、分割回文串：退出条件 + slice 边界

`分割回文串`（把 `s` 切成若干段、每段都是回文）正好练"三步定位法"和"切一刀"的边界。

- **进度条 = 剩余串 `str`**，越切越短，退出条件是 `str === ''`（切光才算一套完整方案）。
- **每步选择 = 切一刀取前缀** `str.slice(0, i)`，`i` 是刀的位置。
- **门卫 = `judge(前缀)`**：前缀是回文才允许 `dfs` 往下，否则这刀作废。这就是本题的约束。

最易错的边界：`for` 要写 `i <= str.length`，不是 `<`。

```javascript
for (let i = 1; i <= str.length; i++) {
  // <= 才能把整段切下来
  const tmp = str.slice(0, i);
  if (judge(tmp)) {
    path.push(tmp);
    dfs(str.slice(i)); // 切到 i=length 时，slice(i)=""，下层命中退出
    path.pop();
  }
}
```

原因：`slice(0, i)` 要切出整段，`i` 得能取到 `str.length`。这一刀有两个作用，一是把"剩余串整个当一段"这个解切出来，二是让 `dfs(str.slice(i))` 收到空串、直达退出条件。写成 `<`，最后一个字符永远切不掉，剩余串永远空不了，整条递归到不了终点，不只是少一个解。

补充：`slice` 从末尾往后切（`i` 超过内容）只会返回 `""`，不报错，所以可以放心让 `i` 取到 `str.length`。

## 六、状态传递：闭包 vs 参数（最容易踩坑）

回溯里所有状态（`sum`、`path`、`curStr`…）都要在这条线上选边：

| 状态类型           | 闭包式（改 + 撤）             | 参数式（送新值、免撤）                 |
| ------------------ | ----------------------------- | -------------------------------------- |
| `sum`（数字）      | `sum += x` … `sum -= x`       | `dfs(i, sum + x)`                      |
| `path`（数组）     | `path.push(x)` … `path.pop()` | `dfs(i, [...path, x])`（每层造新数组） |
| `curStr`（字符串） | 外部拼接 + slice 撤           | `dfs(curStr + ch, i+1)`                |

两种方式二选一：闭包就自己改、自己撤；参数就只送新值、不碰自己的变量。选了参数是图省去撤销，那就别再手动改它。

### 经典 bug：混用

```javascript
sum += candidates[i]; // 闭包式：改了本层的 sum 储物格
dfs(i, sum); // 参数式：又把它当参数传
path.pop(); // 只撤了 path，没撤 sum！
```

`sum += x`（改自己的储物格）和 `sum + x`（送出一个新值）是两回事。for 循环的每个兄弟分支都要读本层那个 `sum` 储物格，所以只能送新值，不能改储物格。真要改，就改完立刻 `-=` 擦干净。

### 实战搭配

- `path` 用闭包 + push/pop，省得每层复制整个数组（`[...path]` 是 O(n)）。
- `sum` 用参数传值，数字复制是 O(1)、几乎免费，还省了撤销。

## 七、底层机制：栈为什么能"保存"和"回退"

把调用栈想成一摞盘子。每次 `dfs(...)` 就造一个新盘子放最上面，盘子上放着这一层专属的参数、局部变量 `i`，和一个"我从上层哪一行来的"书签。

- **保存**：下层盘子压上来时碰不到下面盘子里的东西，所以上层的 `sum`、`i` 原封不动地躺着。不是谁主动去存，是被压在下面动不了。
- **回退**：上层盘子执行完被扔掉，露出下面的盘子，照着书签回到"调用的下一行"继续。下层的值从头到尾没被动过，扔掉上层自然露出原值。

### 闭包和栈的关系

- **参数**（`sum`、`i`、`start`）住在盘子里，栈自动保存和回退，你不用管。
- **闭包变量**（`path`、外部 `sum`）住在所有盘子外面的大房间里，全程只有一份，栈管不着，得你手动 `push/pop`、`+=/-=` 去还原。

栈只自动照顾盘子里的东西，照顾不到盘子外的。参数在盘子里免撤销，闭包在盘子外必须手动撤销。混用出错，就是把盘子外的东西当盘子里的用了。

### 更精确：盘子里放的不是数组本身，是"便利贴"

- **数字**（`i`、`sum`）小，本体直接住在盘子里，每层一份互不干扰，栈自动存和回退。
- **数组 / 对象**（`path`）大，本体放在桌上（堆 heap），全程只有一份；盘子里只放一张指向它的便利贴（引用/地址）。所有层的便利贴都指向桌上同一个 `path`。
  - 所以 `path.push(x)` 改的是桌上那个数组，每一层看到的都跟着变（因为是同一个）。
  - 扔盘子只扔盘子（连同便利贴），碰不到桌上的数组，所以 `path` 不会自动回退，得手动 `pop`。
- 推论：数组当参数传，传的也只是便利贴。想给下层一份真正独立的副本，得用 `[...path]` 在桌上复制一个新数组。

数字和数组的区别就在这里：数字本体住盘子里，数组本体住桌上、盘子里只有便利贴。这也是为什么 `sum` 传参免撤销、`path` 共享必须手动 pop。

### pop 不是紧跟 push 执行的，它被 dfs "挡住"了

`push → dfs → pop` 三行里，`pop` 要等中间那个 `dfs`（下一层的全部过程）跑完才轮到执行。所以上层放的东西，在下层期间一直留在 `path` 里。

以 `n=1`（括号生成）走一遍，盯着 `path` 看：

```
【第0层】dfs(0,0)  path=[]
  放左 push '(' → path=['(']
  dfs(1,0) ↓ 进第1层（左括号没 pop，还在！）
  │  【第1层】dfs(1,0)  path=['(']
  │    放右 push ')' → path=['(', ')']   ← 上层的 ( 还在，所以这里凑成两个！
  │    dfs(1,1) ↓ 进第2层
  │    │  【第2层】dfs(1,1)  right===n 满足
  │    │    res.push(path.join(''))  📸 把 "()" 拍照存进 res → return
  │    pop ')' → path=['(']
  │  （第1层结束返回）
  pop '(' → path=[]    ← 第0层的 pop 现在才执行
（结束）

path 最终 = []（空）   res 最终 = ["()"]（照片还在！）
```

### path 归零 ≠ res 归零

- **path 是"正在走的路"**：一路 push/pop，递归结束时被擦得干干净净、归零。
- **res 是"沿途拍的照片"**：`path.join('')`（或 `[...path]`）在收集那一刻拷贝出一个全新独立的值存进 res，之后和 path 再无关系，后面 path 怎么 pop 都碰不到它。

收集时必须拷一份快照，就是这个道理：path 最后会被 pop 空，但 res 里存的是拷贝，不受影响。`res.push(path.join(''))` 相当于拍照存档，被拍的人后面怎么变，照片都不变。

### 验证靠运行，别脑补

写完直接跑（`node -e "..."` 打印几个用例），别在脑子里推断对错。脑内推演很容易误判。写这题时一度以为 `right === n` 不够、要 `left===n && right===n`，实跑才发现：门卫 `right < left` 保证了 `right ≤ left ≤ n`，`right` 到 `n` 时 `left` 必然也到 `n`，所以 `right === n` 单独判断就对，还更简洁。

## 八、什么时候用 for，什么时候用平行 if

分叉有两种形式，看的不是"选项几个"，是"候选从哪来"：

| 问自己       | 用 `for`                        | 用平行 `if` 分支           |
| ------------ | ------------------------------- | -------------------------- |
| 候选是什么   | 一个数组/字符串（**数据结构**） | 几个写死的动作（**代码**） |
| 数量何时确定 | **运行时**才知道，且可能变      | **写代码时**就定死         |
| 每个候选逻辑 | **相同**（统一 push→dfs→pop）   | **不同**（各有各的门槛）   |
| 例子         | 子集、组合总和、电话号码        | 括号生成（放左 / 放右）    |

- **`for`**：像去水果店，老板递你一袋水果（`letters`、`candidates`），你不知道袋里几个，只能一个一个掏。哪怕这次恰好只有 1 个也照样用 for，因为写代码时不知道会是几个。选项只有 1 个，不是不用 for 的理由。
- **平行 `if`**：像面前两个写死的按钮（左/右），你明确知道就这俩，而且每个按钮亮不亮的条件还不同，就分别判断。

括号题硬用 `for (const ch of ['(', ')'])` 也能写，但要在循环体里再用 `if (ch === '(')` 把左右拆开，等于先合并再拆开、白绕一圈。候选规则不同的时候，for 反而添乱，直接写平行 if 更贴合。

## 九、分叉 = 平行 if（不是 if...else）

回溯里"这一步能放左、也能放右"这种分叉，别用 `if...else`：

```javascript
// ❌ 错：else 让它变成"二选一"，放了左就不放右了
if (能放左) {
  放左;
} else if (能放右) {
  放右;
}

// ✅ 对：两个独立平行的 if，两条路都要试
if (left < n) {
  path.push("(");
  dfs(left + 1, right);
  path.pop();
}
if (right < left) {
  path.push(")");
  dfs(left, right + 1);
  path.pop();
}
```

平行 if 为什么就实现了分叉：第一个 if 里的 `dfs` 会完整跑完整棵子树、返回、pop，之后才轮到第二个 if。于是同一个节点先把"左"这条路走到底、回来，再走"右"，等于一个节点长出两个孩子。

要几条分叉就写几个平行 if（或 for 转几圈），别用 else 串成二选一。

### 门卫心法

回溯的关键不在"现在该做什么"。它给每个选择配一个门卫（准入条件），把所有选择都摆出来，让门卫自己放行或拦截。

- "只能放左"：门卫A（`left<n`）放行，门卫B（`right<left`）拦住，只走左。
- "只能放右"：门卫A 拦住，门卫B 放行，只走右。
- "左右都能放"：两个门卫都放行，两条都走。

你不用去想"当前处于哪种局面"，局面是所有门卫放行结果自动拼出来的。你只负责给每个选择单独定一条"什么条件下允许"的规则。这跟人脑"先列举所有情况再决策"的习惯相反，所以一开始很难想到。

## 十、写递归时，不要在脑子里追踪执行

"不敢写递归"的常见原因，是以为写之前得能在脑内把 push/dfs/pop 跑一遍。这个前提是错的，人脑几乎做不到，也不需要。

写递归和追踪递归执行是两件事：

|            | 写递归           | 追踪执行           |
| ---------- | ---------------- | ------------------ |
| 要懂堆栈吗 | **不需要**       | 需要               |
| 难度       | 简单（只想一层） | 极难（人脑容易乱） |
| 何时用     | **写代码时**     | 调试 / 建立直觉时  |

### 写代码只靠"单层契约"：回答三个问题

想象自己只是某一层的员工，看不到上层也看不到下层，只回答：

1. **什么时候交货？**（收集 / 终止）→ 括号：`left===n && right===n`
2. **我这层有哪些选择？每个的门槛是什么？**（几个选择就几个平行 if / 或一个 for）→ 放左 `left<n`、放右 `right<left`
3. **每个选择怎么"选 → 交给下层 → 撤销"？**→ `push → dfs → pop`

回答完，代码就写完了，全程不用在脑子里跑 push/pop 顺序，那是栈的活。

写递归其实不需要理解它怎么执行也能写对。你写好一层的规矩，栈负责把这层规矩在很多层里叠起来、拆下来。越不去追踪它，反而越写得对。

### 治"不敢写"的练习法

强制自己不许脑内模拟执行，只做三步：写终止 → 写每个选择的门槛 → 每个填 push/dfs/pop。写完别脑内验证，直接跑代码，用运行结果代替脑内模拟。

## 十一、学习策略（给未来的自己）

- 新类型题：先画全决策树建立模型；熟练后转为只想"三要素"，不再脑内模拟递归。
- 关注本层责任（这一步选什么、要不要收、要不要撤），执行过程交给栈。
- 记住画面（一排数捡 / 填格子 / 篮子凑数），术语只是画面的标签。

## 十二、网格类回溯（C 类）：单词搜索为什么难一个台阶

`单词搜索`（在二维矩阵里找单词路径）比前面几题难，原因是它一次叠了 5 个新变化。逐条对比就知道卡在哪：

| 维度           | A/B 类（子集·组合·括号）                 | C 类（单词搜索）                     |
| -------------- | ---------------------------------------- | ------------------------------------ |
| **往哪走**     | 沿一条线往后（start++、下一位、放左/右） | 二维四面开花，上下左右还能绕回       |
| **怎么防重踩** | `start` 指针天然挡住（结构性的）         | 主动改数据盖 `'#'`，用完再揭掉       |
| **路径记哪**   | 显式 `path` 数组装着                     | 没有 path，痕迹记在 `board` 自己身上 |
| **入口**       | 一个固定入口 `dfs(0,0)`                  | 每个格子都可能是起点，外套双层循环   |
| **怎么出结果** | `push` 收集（void 型）                   | boolean 一路 `return true` 抬回顶层  |

任意一条单拎出来都不难，难在密度，5 条同时压过来。觉得磕绊很正常。

### 两个反直觉的点

**① 路径不用数组装，记在数据本身上。**
前面题养成的直觉是"回溯 = path.push/pop"。这题的"走过"只是为了防止重踩、不是要收集答案，所以直接在原数据上做记号更省事：`board[y][x]='#'` 相当于 push，还原相当于 pop，盘子换成了网格格子。

**② 带返回值的回溯，比收集型难。**
子集、括号是"走到就 push，不关心返回值"。这题问的是"找到没有"，一个 `true` 要从最深处一层层抬回最外面，中间任何一层收到下层的 `true` 都得立刻 `return true` 往上递。这个"往上抬"的链条比"到底了 push 一下"更烧脑。

### 网格 DFS 五步模板

触发信号：矩阵/网格里找路径·连通块·走迷宫，加上上下左右相邻、同格子不能重复用。命中就套这套：

```
dfs(x, y, 进度):
  ① 越界？          → return false      // 先挡边界
  ② 当前格不匹配？  → return false      // 再挡不合法
  ③ 进度到头了？    → return true       // 成功出口
  ④ 盖章 board[y][x]='#'                // 相当于 push
  ⑤ 四方向轮流试，任一 true 就 return true
     还原 board[y][x]=原值              // 相当于 pop
     return false                       // 四路都不通，明确交卷
```

外面再套"每个格子当起点试一遍"：`if (dfs(起点)) return true;`，全试完 `return false`。

### 坐标约定：一次钉死 x / y

"x 是横轴"和"x 是行下标"不能同时成立。横轴是一行里从左往右走，变的是列。

| 符号 | 含义        | 管谁       | 边界                |
| ---- | ----------- | ---------- | ------------------- |
| `x`  | 横轴 / 左右 | **列**下标 | `0 ≤ x < m`（列数） |
| `y`  | 纵轴 / 上下 | **行**下标 | `0 ≤ y < n`（行数） |

JS 二维数组天生是 `board[行][列]`，所以永远写 `board[y][x]`（y 在前）。脑子念 "x,y"、手里写 `[y][x]` 的别扭感就来自这里，认定"y=行=第一个下标"就顺了。

### 三个实战坑

1. **方向变量名别撞车**：外层双循环的起点坐标别再叫 `i,j`，方向位移量用 `dx,dy`，然后 `dfs(x+dx, y+dy)` 一一对应，不用猜哪个配哪个。
2. **还原写 `board[y][x]=原字母` 靠一个前提**：门卫 `word[index] != board[y][x]` 已经保证能走到盖章这步的格子原值 = `word[index]`。更稳的写法是 `const tmp=board[y][x]` 先存后还，不依赖这个推理。
3. **别忘显式 `return false`**：四方向全败时若不写，返回 `undefined`（假值）能碰巧过，但不干净。

### 和前面题的分界

A/B 类里 path 是要收集的答案，所以外挂一个 `path` 数组；C 类（网格）里"走过"只是防重踩，记号直接盖在数据本身上。这是网格回溯和前面所有题最大的区别。
