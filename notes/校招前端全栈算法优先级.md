# 校招前端 / 全栈：算法优先级

> 适用人群：校招生，前端岗和全栈岗都投。
> 一句话结论：算法以 Easy / Medium 为主，Hard 少碰；链表和树基本必问；前端手写题是后端候选人没有的加分项，别丢。
>
> **来源说明**：下面每条都标了出处。这些数据来自 2025-2026 的面经帖、刷题路线和岗位调查，**不是精确统计**，反映的是趋势而非确切频率。带百分比的地方尤其要当参考看，不要当铁律。信息可能过期，投递前按目标公司的实际情况再核对一次。

---

## 一、先分清：前端 / 全栈 / 后端不是一套标准

牛客校招内推群的岗位调查把门槛讲得很清楚（来源：[牛客校招求职调查](https://m.nowcoder.com/discuss/353159375311282176)）：

| 岗位 | 算法难度 | 刷题量 | 额外要求 |
| ---- | ---- | ---- | ---- |
| 算法岗 | 刷到 Hard | 最多 | CV / NLP / 推荐手撕题 |
| 后端 | Medium 为主（占 80-90%） | 200-300 | 系统设计 |
| **前端** | **要求没特别高**，Medium 占 70-80% | ~200 | **链表、树基本必问** + 前端手写题 |

你两者都投，等于要覆盖：**前端手写题（后端没有）+ 接近全栈的算法广度**。好消息是校招生深度要求比社招低，Hard 极少。

## 二、校招的三个事实（决定你怎么分配时间）

**1. 校招算法权重比社招还高。** 校招看基础和潜力，你没多少项目可聊，算法和计算机基础就是主筛子（来源：[校招 vs 社招侧重点，CSDN 2026-05](https://blog.csdn.net/mashibingjiaoyu/article/details/160769855)）。

**2. 难度以中等和简单为主。** 大厂近 50 份校招笔试统计：简单约 25%、中等约 50%、较难约 20%、困难约 5%（来源：[应届生算法刷到什么程度，CSDN 2026-05](https://blog.csdn.net/HHX_01/article/details/161053973)）。中等加简单占了四分之三，别一头扎进 Hard。

**3. 实习面试更浅。** 实习考的核心数据结构就六样：数组、字符串、哈希、链表、栈、二叉树；几乎不考系统设计，Hard 罕见（来源：[LeetCode for Interns，yeetcode.site 2025-09](https://www.yeetcode.site/blog/leetcode-internship-interview)）。

## 四、前端手写题主线（后端候选人没有的优势项）

这块白板手写，后端基本不考，前端和全栈是加分项。你的 [前端手写题/](../前端手写题) 目录已经建好这些（来源：[前端实习算法必刷路线，CSDN 2026-01](https://blog.csdn.net/ya3288426755/article/details/156491882)；[牛客校招调查](https://m.nowcoder.com/discuss/353159375311282176)）。

必会：

- 防抖、节流（带立即执行和取消）
- 深拷贝（WeakMap 处理循环引用）
- Promise.all / Promise.race
- 并发调度器（限制并发数，面经标"字节核心必考"）
- LRU 缓存（Map + 双向链表思想，标"字节、小红书超高频"）→ [前端手写题/LRU缓存.js](../前端手写题/LRU缓存.js)
- 手写简易 Promise（pending → fulfilled 状态流转 + then）
- 数组扁平化、去重、发布订阅、柯里化
- 列表转树 / 树转列表

## 五、建议的推进节奏

1. 手撕类和算法类**并行**：每天一道手写题保持前端手感，一到两道算法题按上面 P0→P1→P2 走。
2. 算法先扫 P0 五个板块，链表和二叉树优先，因为它们"基本必问"且你已有底子。
3. 每道做完口述一遍思路和复杂度，这是面试真正考的东西（面试官考的是你会不会想，不是背没背过，来源：[应届生算法刷到什么程度](https://blog.csdn.net/HHX_01/article/details/161053973)）。
4. Hard 题只挑高频的几道（76 最小覆盖子串、25 K 个一组翻转），不铺开。
