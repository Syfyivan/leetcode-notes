# 限流算法

## 核心回答（面试口述版，1 分钟能讲完）

限流是把请求速度压到系统能扛的范围，超了回 429。四种：固定窗口、滑动窗口、漏桶、令牌桶。令牌桶允许短时突发，漏桶输出恒定。单机用内存计数；多实例必须把计数放到 Redis，用 Lua 保证读改写原子，否则每个节点各自放行，总和会翻倍。

## 展开

1. 固定窗口/滑动窗口/漏桶/令牌桶

   - **固定窗口**：每秒一个计数器，到点清零。最好写。
   - **滑动窗口**：把 1 秒切成 N 格，或用 ZSet 存时间戳，窗口平滑很多。
   - **漏桶**：队列恒定速率出，进得太快直接溢出。形状平滑，突发会被削平。
   - **令牌桶**：以恒速往桶里放令牌，请求要带走一枚。桶里有存货时可以突发，存货为 0 就拒。Nginx `limit_req` 的 burst 就是这个思路。

2. 各自优缺点、突发流量处理

   固定窗口有临界突刺：0.9 秒打满，1.1 秒再打满，瞬时 2 倍。滑动窗口能压下去，Redis 这边成本高一点。漏桶对下游最友好，用户侧可能排队。令牌桶对秒杀开始那一下更友好，下游要能吃 burst。网关层用令牌桶居多。

3. 单机限流 vs 分布式限流（Redis+Lua）

   单机：Guava RateLimiter、漏桶计数，进程重启清零。
   分布式：key 按 `user:id` 或 `api:/pay`，Lua 里 INCR + EXPIRE 或令牌计算。集群化 Redis 要选同一 slot（hash tag `{user}:9`）。网关（Kong、Nginx、Sentinel）通常自带。限流维度：IP、用户、接口、全局限额叠着来。

## 代码 / 例子

```text
-- 固定窗口 Lua
local n = redis.call('INCR', KEYS[1])
if n == 1 then redis.call('EXPIRE', KEYS[1], ARGV[1]) end
if n > tonumber(ARGV[2]) then return 0 end
return 1
-- KEYS[1]=rate:/pay:uid, ARGV[1]=1秒, ARGV[2]=20
```

## 常见追问

- Q: 令牌桶和漏桶的核心区别？
  A: 漏桶：请求进桶，按固定速率流出去，进太快溢出，输出无突发。令牌桶：按固定速率发令牌，请求有令牌就立刻过，桶容量决定最大突发。比喻：漏桶是排队出站，令牌桶是先囤通行证。保护写库用漏桶更稳，网关入口用令牌桶体验更好。
- Q: 固定窗口的临界突刺问题怎么解决？
  A: 改滑动窗口：多格计数加权，或 ZSet 记请求时间 `ZREMRANGEBYSCORE` 掉窗口外再 `ZCARD`。简单折中：窗口改小（100ms）突刺绝对值变小。令牌桶本身没有整秒翻倍这个问题。

## 自己的易错点 / 之前答崩过的地方

- Redis INCR 和 EXPIRE 分两条，第一次 INCR 后进程挂了，key 永不过期，接口被永久卡死。必须 Lua 或 `SET key 1 EX 1 NX` 初始化。
- 限流维度只按 IP，NAT 出口把一个公司全挡了。登录后按 uid。
- 把限流当防刷验证码的替代。限流抗的是流量，防刷还要设备指纹和行为。
