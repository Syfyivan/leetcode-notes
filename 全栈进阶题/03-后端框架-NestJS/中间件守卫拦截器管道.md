# 中间件守卫拦截器管道

## 核心回答（面试口述版，1 分钟能讲完）

一次请求在 Nest 里顺序是：中间件 → 守卫 Guard → 拦截器 Interceptor 的 `next` 前半 → 管道 Pipe → handler → 拦截器后半（RxJS `map`）→ 异常过滤器（若抛错）。中间件碰原始 `req/res`，和 Express 兼容。Guard 实现 `CanActivate`，返回 false 就 403。Pipe 实现 `PipeTransform`，做 DTO 校验和类型转换。Interceptor 实现 `NestInterceptor`，切执行前后，打日志、包响应、缓存。

## 展开

1. 四者的执行顺序（中间件→守卫→拦截器→管道→handler）

   ```
   Middleware → Guard → Interceptor(pre) → Pipe → Controller
        ↑                                         |
        └──────── ExceptionFilter ← Interceptor(post)
   ```

   全局中间件先于模块中间件。多个 Guard 全过才继续。拦截器像洋葱，可套多层。管道按参数从左到右。handler 抛的 `HttpException` 被 `ExceptionFilter` 接。

2. 各自的职责边界

   - **Middleware**（`NestMiddleware`）：改请求、打 access log、body parser 已经在适配器里。拿不到执行上下文里的 handler 元数据。
   - **Guard**：鉴权、角色。读 `Reflector` 上的 roles。不该改响应体。
   - **Interceptor**：AOP。`tap` 记耗时，`map` 包 `{ code: 0, data }`，`catchError` 转异常。返回值是 `Observable`。
   - **Pipe**：`ValidationPipe` + `class-validator` 验 body；`ParseIntPipe` 把 `:id` 转 number。失败丢 `BadRequestException`。

3. Guard 做鉴权、Pipe 做校验转换、Interceptor 做切面

   JWT 在 Guard 里验签，把 payload 挂 `request.user`。`ValidationPipe({ whitelist: true, transform: true })` 丢掉 DTO 没声明的字段并转型。超时、缓存、事务切面用 Interceptor，因为能包住整个 `handle()` Observable。别在 Pipe 里查库做权限，那是 Guard 的事。

## 延伸

- 相关题：装饰器与元数据反射。Guard 读的 roles 就是 `SetMetadata` 贴上去的。
- 对比：cookie-parser、helmet 只能当中间件；统一包 `{ code, data }` 用拦截器。中间件拿不到 handler 元数据。
- 加码：公开接口用 `@Public()` 跳过全局 JWT Guard。别为了登录页把全局守卫关掉。

## 代码 / 例子

```ts
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}
  canActivate(ctx: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<string[]>('roles', [
      ctx.getHandler(), ctx.getClass(),
    ]);
    const user = ctx.switchToHttp().getRequest().user;
    return !roles || roles.includes(user?.role);
  }
}

@Injectable()
export class TransformInterceptor implements NestInterceptor {
  intercept(_: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(map((data) => ({ code: 0, data })));
  }
}
```

## 常见追问

- Q: 拦截器和中间件都能改响应，怎么选？
  A: 中间件看到的是 Express `res`，handler 还没跑，要自己 `res.on('finish')` 才能在事后做事，也拿不到控制器返回值。拦截器拿到 `next.handle()` 的 Observable，能改返回对象、统一包一层、按元数据分支。和 Nest 路由模型绑定的逻辑用拦截器；必须用 Express 生态（cookie-parser、helmet）用中间件。
- Q: 全局管道和局部管道优先级？
  A: 先跑全局，再跑 controller / 参数上的。`app.useGlobalPipes(new ValidationPipe())` 之后，参数上的 `ParseIntPipe` 仍会跑。后跑的能看到前面转换过的值。守卫、拦截器同样：全局 → controller → method。注意全局 Guard 在每个路由都跑，把 JWT 解析放全局，公开接口用 `@Public()` 元数据跳过。

## 自己的易错点 / 之前答崩过的地方

- 在中间件里想读 `@Roles()`。中间件没有 `ExecutionContext.getHandler()`。
- Guard 返回 `false` 期望自己写 401 文案。Nest 直接丢 `ForbiddenException`（403）。要 401 自己 `throw new UnauthorizedException()`。
- 拦截器里 `next.handle()` 忘了 return，响应丢失。
- `ValidationPipe` 没开 `transform`，`@IsInt()` 对着字符串永远失败。
