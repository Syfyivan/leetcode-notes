# 异常过滤器与统一响应

## 核心回答（面试口述版，1 分钟能讲完）

Nest 里可抛 `HttpException`（`BadRequestException`、`UnauthorizedException`、`NotFoundException` 等），默认过滤器把它变成对应 HTTP 状态码和 JSON。业务要统一成 `{ code, message, data }` 时，自己写 `@Catch()` 的 `ExceptionFilter` 全局挂上，成功响应用 `Interceptor` 的 `map` 包一层。未知错误要变成 500，message 对外只说「内部错误」，堆栈写日志，别塞进响应体。

## 展开

1. ExceptionFilter、HttpException

   `HttpException` 带 `status` 和 `response`。`throw new NotFoundException('user')` 默认 404。过滤器实现 `ExceptionFilter`，`catch(exception, host)` 里 `host.switchToHttp().getResponse()` 自己 `status().json()`。`@Catch(HttpException)` 只接这一类；`@Catch()` 空参接一切。

2. 全局异常过滤器统一错误格式

   `app.useGlobalFilters(new AllExceptionFilter(logger))` 或 provider `APP_FILTER`。过滤器里分支：`HttpException` 用它的 status 和 message；`QueryFailedError` 这类 ORM 错映射 400/409；其余 500。把 `request.method`、`url`、`exception.stack` 打到日志。校验失败时 `ValidationPipe` 抛的 `BadRequestException` 里 `message` 可能是数组，要摊平。

3. 拦截器统一包裹成功响应

   `TransformInterceptor`：`next.handle().pipe(map(data => ({ code: 0, data })))`。注意文件下载、SSE 不要包。可以用 `@SkipWrap()` 元数据让拦截器放过。错误别在拦截器 `catchError` 里再包一层和过滤器打架，错误交给 Filter。HTTP 状态码仍按语义：创建 201，空 204，错误 4xx/5xx；`code` 是业务码，不要只用 200 配业务码冒充一切成功。

## 代码 / 例子

```ts
@Catch()
export class AllExceptionFilter implements ExceptionFilter {
  constructor(private readonly log: Logger) {}
  catch(e: unknown, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    const req = host.switchToHttp().getRequest();
    const status = e instanceof HttpException
      ? e.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;
    const message = e instanceof HttpException ? e.message : 'internal error';
    this.log.error(req.method, req.url, e instanceof Error ? e.stack : e);
    res.status(status).json({ code: status, message, data: null });
  }
}
```

## 常见追问

- Q: 业务错误码和 HTTP 状态码怎么配合？
  A: HTTP 状态码给网关、浏览器、监控用：401 未登录，403 没权限，404 没有资源，409 冲突，422 校验失败，500 未知。body 里的 `code` 给前端分支：`10001` 库存不足、`10002` 优惠券过期。两者一起返回。别全部 200 再在 body 里写失败，缓存和探针都会误判。
- Q: 怎么把未知异常兜底成 500 而不泄漏堆栈？
  A: 全局 `@Catch()` 判断是不是 `HttpException`。不是就 status=500，响应只给固定文案。`stack`、SQL、内部路径写 Logger / Sentry。开发环境可以用 `NODE_ENV !== 'production'` 才把 `message` 透出。别 `JSON.stringify(err)` 直接回给客户端。

## 自己的易错点 / 之前答崩过的地方

- 拦截器和过滤器都改错误体，客户端收到两层包或丢了 status。
- `throw 'not found'` 抛字符串，过滤器当未知 500。要抛 `HttpException`。
- 过滤器里再 throw，Nest 没有第二张网，进程打未处理拒绝。
