# 装饰器与元数据反射

## 核心回答（面试口述版，1 分钟能讲完）

Nest 的路由、注入、守卫全靠 TypeScript 装饰器和 `reflect-metadata`。`@Controller('users')`、`@Get(':id')` 在类和方法上 `SetMetadata`，启动时 `DiscoveryService` 扫这些元数据拼路由表。`emitDecoratorMetadata: true` 会给构造函数参数补 `design:paramtypes`，IoC 才知道要注入哪个类。自定义参数装饰器用 `createParamDecorator`，从 `ExecutionContext` 里抠 `request.user`。

## 展开

1. TS 装饰器语法、reflect-metadata

   装饰器是函数，在声明时调用。类装饰器拿到 constructor，方法装饰器拿到 prototype + key。`Reflect.defineMetadata(key, value, target, propertyKey)` 把键值贴到对象上，`Reflect.getMetadata` 读回来。Nest 封装成 `SetMetadata('roles', ['admin'])`。这套是 ES 旧提案的 experimentalDecorators，和现在 stage 3 装饰器语义不完全一样，Nest 10 仍走实验开关。

2. @Controller/@Get 等如何靠元数据工作

   `@Controller('users')` 记下 path 前缀。`@Get(':id')` 记下 method + path。`@Param('id')`、`@Body()` 记下参数从哪取。`NestFactory.create` 之后，`Injector` 扫每个模块的 controller，读元数据，向底层 HTTP 适配器（Express / Fastify）注册。所以装饰器本身不处理请求，只往原型上贴数据。

3. 自定义装饰器（参数装饰器取当前用户）

   `createParamDecorator((data, ctx) => { const req = ctx.switchToHttp().getRequest(); return data ? req.user?.[data] : req.user; })`。守卫里先前把 user 挂到 request 上，参数装饰器只负责取。权限码用 `SetMetadata('roles', roles)` + `Reflector.getAllAndOverride` 在 Guard 里读。

## 代码 / 例子

```ts
import { createParamDecorator, ExecutionContext, SetMetadata } from '@nestjs/common';

export const ROLES_KEY = 'roles';
export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);

export const CurrentUser = createParamDecorator(
  (prop: string | undefined, ctx: ExecutionContext) => {
    const user = ctx.switchToHttp().getRequest().user;
    return prop ? user?.[prop] : user;
  },
);

@Get('me')
@Roles('user')
me(@CurrentUser('id') uid: string) {
  return uid;
}
```

## 常见追问

- Q: Nest 是怎么靠装饰器收集路由的？
  A: 启动扫描每个 `@Controller` 类，`Reflect.getMetadata('path', controller)` 拿前缀，再遍历方法上的 `METHOD_METADATA`、`PATH_METADATA` 拼成 `GET /users/:id`，绑到 Express 的 `router.get`。参数装饰器决定 handler 入参怎么从 `req` 填。整个过程发生在 listen 之前。
- Q: emitDecoratorMetadata 有什么用？
  A: tsc 会给类发出 `Reflect.metadata('design:paramtypes', [UsersService])` 这类调用。Nest 的依赖注入靠它推断构造函数参数类型。关掉之后所有注入类型变成 `Object`，报无法解析依赖。`design:type`、`design:returntype` 同样依赖这个开关。只开 `experimentalDecorators` 不够。

## 自己的易错点 / 之前答崩过的地方

- 自己写 `SetMetadata` 时 key 用裸字符串，和别人撞了。抽成常量 `ROLES_KEY`。
- 参数装饰器里取 `req.user`，但 Guard 写在后面。执行顺序是 Guard → 拦截器 → Pipe → handler，自定义装饰器在调 handler 前求值，只要 Guard 先跑过就有 user。
- 把装饰器当运行时切面，在装饰器函数里处理请求。装饰器只在声明时跑一次。
