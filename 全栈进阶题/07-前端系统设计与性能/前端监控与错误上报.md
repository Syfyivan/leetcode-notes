# 前端监控与错误上报

## 核心回答（面试口述版，1 分钟能讲完）

监控分错误和性能。错误：`window.onerror` 接同步脚本错误，`unhandledrejection` 接 Promise，资源失败听捕获阶段的 `error`（因为资源错误不冒泡）。性能：`web-vitals` 的 LCP/INP/CLS，加上 `performance.getEntriesByType('resource')`。上报用 `navigator.sendBeacon`，页面关了也能把数据送出，不挡卸载。线上代码是压缩的，用 sourcemap 在服务端还原栈，浏览器拿不到 map 文件。

## 展开

1. 错误监控（window.onerror / unhandledrejection / 资源错误）

   `window.onerror = (msg, src, line, col, err) => ...`，能拿到同步 throw。`addEventListener('unhandledrejection', e => e.reason)`。`<script>` / `<img>` 失败：`window.addEventListener('error', handler, true)` 捕获。框架还有 Vue `app.config.errorHandler`、React Error Boundary，只挡渲染错误，挡不住事件里的异步。跨域脚本常变成 `Script error`。

2. 性能监控（Web Vitals、performance API）

   `PerformanceObserver` 观察 `largest-contentful-paint`、`layout-shift`、`event`。资源 timing 看 DNS/TCP/传输。长任务 `entryType=longtask`。采样后和错误共用一个上报通道，带上页面、版本、uid、网络。

3. 上报方式（sendBeacon）、sourcemap 还原

   `fetch keepalive` 或 `sendBeacon('/log', blob)`。sendBeacon 不期待响应，关闭页也发。体积太大要截断栈和面包屑。sourcemap 只放内网，CI 上传到 Sentry / 自建，用 `@ampproject/remapping` 把 `app.js:1:2345` 还原成 `src/foo.ts:80`。map 文件千万别跟静态资源一起公开。

## 延伸

- 相关题：前端性能优化体系。Web Vitals 上报就走这套通道。
- 对比：`sendBeacon` 不挡卸载；同步 XHR 在 unload 里会被浏览器砍。SSR 错误和浏览器错误要分渠道。
- 加码：上报函数里再 throw 会打成死循环。整段必须 `try/catch` 包死。sourcemap 上 CDN，源码等于公开。

## 代码 / 例子

```js
window.addEventListener('error', (e) => {
  const t = e.target;
  if (t !== window) report({ type: 'resource', src: t.src || t.href });
}, true);

window.onerror = (msg, src, line, col, err) => {
  report({ msg, src, line, col, stack: err && err.stack });
};

window.addEventListener('unhandledrejection', (e) => {
  report({ msg: String(e.reason) });
});
```

## 常见追问

- Q: 跨域脚本报错为什么是 Script error，怎么解决？
  A: 浏览器对跨域脚本隐藏细节，防探测内网。解决：脚本响应加 `Access-Control-Allow-Origin`，标签加 `crossorigin="anonymous"`，这样 onerror 能拿到真消息和栈。CDN 要配 CORS。jsonp 式脚本没法这么做。
- Q: 上报量太大怎么采样、怎么不阻塞主流程？
  A: 错误全量（或按 uid hash 1% 抽样但保证同一用户连续），性能指标按 10%~20% 采样。同屏去重：同一 `msg+stack` 一段时间内只报一次，带上 count。上报放队列，`requestIdleCallback` 或每 5 秒 flush，最后 `sendBeacon`。别 `console.log` 同步 `JSON.stringify` 大对象。

## 自己的易错点 / 之前答崩过的地方

- 只绑 `window.onerror`，图片 404 和 Promise 拒绝全漏。
- sourcemap 上了 CDN，源码等于公开。
- 在上报函数里再 throw，形成死循环。上报必须 try/catch 包死。
