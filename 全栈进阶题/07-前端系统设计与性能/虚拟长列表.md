# 虚拟长列表

## 核心回答（面试口述版，1 分钟能讲完）

一万行别真渲染一万个 DOM。只渲染可视区加上上下各几条缓冲，其余用一根占位把总高度撑开。滚动时算 `startIndex = scrollTop / 行高`，用 `transform: translateY(start*rowHeight)` 把这一屏挪到正确位置。定高直接除；不定高先估一个高度，渲染后 `getBoundingClientRect` 写回，前缀和 + 二分找 startIndex。和分页配合时，数据数组可以继续往后 append，窗口算法不变。

## 展开

1. 只渲染可视区 + 缓冲区的原理

   `visible = ceil(containerHeight / itemHeight)`，`start = floor(scrollTop / itemHeight) - overscan`，`end = start + visible + 2*overscan`。列表总高度 `N * itemHeight` 放在内层 phantom 上，滚动条才是满的。缓冲（overscan）避免快速滑时露白。滚动回调里用 `requestAnimationFrame` 节流，或直接听 `scroll` 算。

2. 定高、不定高（预估+测量）两种实现

   定高：下标和 offset 线性，O(1)。
   不定高：维护 `offsets[]` 前缀和。第一次用 `estimatedHeight`（比如 80px）填。某行挂载后量真实高度，更新前缀和。根据 `scrollTop` 在 offsets 上二分找第一行。react-window 的 `VariableSizeList` 就是这个。高度变化（展开行）要通知列表 `resetAfterIndex`。

3. 滚动时的 DOM 复用、占位撑高

   不必每次销毁节点，池子里的 div 改内容和 `translateY` 即可，类似 iOS 的 cell reuse。占位撑高不要用 10000 个空节点，一个 `height: total` 的 div 就行。锚点滚动（从详情返回保持位置）要记下 `index + 行内偏移`，数据刷新后按 id 找回来。

## 代码 / 例子

```js
const H = 48, OVER = 5;
function slice(scrollTop, viewH, n) {
  const start = Math.max(0, Math.floor(scrollTop / H) - OVER);
  const vis = Math.ceil(viewH / H);
  const end = Math.min(n, start + vis + OVER * 2);
  return { start, end, offset: start * H, total: n * H };
}
// inner.style.height = total;  window.style.transform = `translateY(${offset}px)`
```

## 常见追问

- Q: 不定高列表的高度怎么算、怎么定位？
  A: 没量过的用估计值，量过的用缓存。`offsets[i+1] = offsets[i] + height(i)`。定位：二分 offsets，找最大的 i 满足 `offsets[i] <= scrollTop`。测量放 `useLayoutEffect` / `ResizeObserver`，避免先画错误高度再跳。估计值和真实值差太多时滚动条会抖，估计尽量接近均值。
- Q: 和分页加载/无限滚动怎么配合？
  A: 虚拟列表管「已经拿到的数据怎么画」，无限滚动管「什么时候再要一页」。接近底部（最后一条进入缓冲）就 `fetchPage`。加载中占位行也算进高度。注意去重和分页游标。搜索换条件要清空高度缓存。数据 10 万本地仍可能内存吃紧，超大就窗口化数据本身（只留附近几页）。

## 自己的易错点 / 之前答崩过的地方

- 用 `margin` 撑偏移，和 `transform` 混用，出现缝。统一 `translateY`。
- 不定高用定高算法，滚动一段后错位，点到的不是那一行。
- 在 `scroll` 里 `setState` 整表重渲染，卡成 10fps。只更新 start/end，行组件 `memo`。
