# 前端性能优化体系

## 核心回答（面试口述版，1 分钟能讲完）

性能拆三个时间段：加载（到有内容）、渲染（到可看可点）、运行时（交互不卡）。指标用 Core Web Vitals：LCP 加载、INP（旧 FID）交互、CLS 布局稳定，外加 FCP、TTFB。优化手段对号入座，别一上来就上微前端。给一个慢页面，先量再改：DevTools Performance / Lighthouse 看瓶颈在网络、主线程还是图片。

## 展开

1. 从加载/渲染/运行时三个维度拆

   - **加载**：DNS、TCP、TLS、TTFB、下载。CDN、缓存、压缩、HTTP/2、减少请求。
   - **渲染**：HTML 解析、CSSOM、阻塞 JS、布局、绘制。关键 CSS、defer、减少重排、骨架屏。
   - **运行时**：长任务、内存、列表。拆任务、虚拟列表、`will-change` 慎用、对象池没必要先别上。

2. 指标（FCP/LCP/CLS/TTI）

   - **FCP**：首次出文字或图。
   - **LCP**：视口最大元素（图、标题块），目标 < 2.5s。
   - **CLS**：元素位移累计，目标 < 0.1，图要写宽高。
   - **INP / FID**：从点到下一帧绘制。长任务 > 50ms 要拆。
   - **TTI**：可稳定交互。实验室指标，线上更看 INP。
   - **TTFB**：首字节，SSR 和网关会影响。

3. 优化手段清单（懒加载、缓存、CDN、拆包）

   图片懒加载 `loading=lazy`（LCP 图不要 lazy）。强缓存带 hash 文件名，HTML 协商缓存。CDN 就近。拆包 + 预加载关键。Service Worker 做离线壳。服务端：gzip、缓存头、边缘 SSR。量的时候区分实验室（Lighthouse）和 RUM（web-vitals 上报）。

## 延伸

- 相关题：前端监控。指标要上报，优化前后用同一套 Web Vitals 对比。
- 对比：加载看网络，渲染看主线程，运行时看长任务。别一上来拆微前端。
- 加码：INP 差就找点击后的长任务，`JSON.parse` 大包丢 worker。虚拟长列表是运行时那一刀。

## 常见追问

- Q: 给你一个慢页面，你的优化排查顺序是什么？
  A: 1) 自己电脑和慢 3G 预设各跑一次 Lighthouse，记下 LCP 元素。2) Network 看是 HTML 慢、JS 大、还是图大。3) Performance 面板看主线程长任务、layout。4) 对症：图压体积、JS 拆、SSR、减第三方。5) 上线后看 RUM 分位数，别只看自己的 Wi-Fi。先改影响 LCP 的那一张图，通常比重构架构快。
- Q: Core Web Vitals 三个指标分别怎么优化？
  A: LCP：压缩并 preload 那张英雄图、CDN、别用客户端才插入的大图、SSR 文本。INP：点后别在主线程 JSON.parse 大包，拆到 worker，防抖输入，减第三方同步脚本。CLS：img/video 预留宽高、字体 font-display、广告位占坑、别在已显示内容上插入横幅。

## 自己的易错点 / 之前答崩过的地方

- 把 FCP 优化当完成，LCP 其实是一张没压缩的 banner。
- 用 `transform` 做动画却去改 `top/left`，每帧 layout。
- 实验室 98 分，真实用户因为机房在海外 TTFB 2 秒。要看分区 RUM。
