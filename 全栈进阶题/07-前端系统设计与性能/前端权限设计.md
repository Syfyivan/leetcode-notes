# 前端权限设计

## 核心回答（面试口述版，1 分钟能讲完）

权限三层：进不进系统（登录态）、进不进页面（路由守卫）、看不看按钮（指令 / 组件）。前端按后端返回的角色或权限码渲染菜单、动态 `addRoute`。前端隐藏只是体验，真正拦截在 API：没权限回 403。刷新页面 Vuex 空了，要先拉用户信息再加路由，否则守卫看见的还是空表，会把人踢回登录或 404。

## 展开

1. 登录态、路由权限、按钮级权限

   登录态：Cookie Session 或 JWT。路由：`beforeEach` 看 token，没有去登录；有 token 再看该 path 是否在允许列表。按钮：`v-permission="'order:export'"` 或组件里 `has('order:export')`。按钮没有权限码就不要渲染，别只是 disable 还能被改 DOM 点出来。

2. 动态路由 vs 前端全量路由 + 后端返回权限码

   动态：后端返回菜单树，前端 `router.addRoute`，没配的页面物理上不存在。适合菜单经常改、多租户。
   全量 + 码：前端写好所有路由 `meta.roles`，守卫里比对。好写，打包会带上管理员页（代码仍可被下载）。
   中后台常用：后端菜单 + 前端按 name 匹配本地组件表，两边都要维护一份组件 map。

3. 菜单与权限的数据结构

   后端给：

   ```js
   [{ path: '/order', name: 'Order', perm: 'order:list',
      children: [{ path: 'export', perm: 'order:export' }] }]
   ```

   权限码用 `resource:action`。角色是码的集合。超管 `*`。菜单树和路由树尽量同一份，避免菜单能点、路由没注册。

## 代码 / 例子

```js
router.beforeEach(async (to) => {
  if (!token()) return '/login';
  if (!store.routesLoaded) {
    const menus = await api.menus();
    addDynamic(menus);
    store.routesLoaded = true;
    return to.fullPath; // 重新走一遍，匹配新路由
  }
  if (to.meta.perm && !store.perms.has(to.meta.perm)) return '/403';
});
```

## 常见追问

- Q: 前端做了权限控制，为什么后端还必须校验？
  A: 前端代码在用户磁盘上，改 JS、直接调 `POST /api/order/export` 就能绕过按钮。权限是服务端的事，token 里的角色、DB 里的 ACL 才算数。前端控制减少误操作和暴露入口。面试就一句话：UI 是提示，API 是关卡。
- Q: 动态路由刷新页面丢失怎么处理？
  A: 动态路由加在内存里，刷新 JS 重跑，只剩静态路由。启动后守卫发现 `routesLoaded === false`，用 cookie 里的登录态请求 `/me` 和 `/menus`，`addRoute` 完再 `next(to.fullPath)`。注意这个「再进一次」避免第一次匹配 404。别把完整路由表塞 localStorage，权限变更后会脏，以服务端为准。

## 自己的易错点 / 之前答崩过的地方

- 刷新死循环：`next(to.fullPath)` 又进守卫，但 `routesLoaded` 没置位。
- 超管前端写死 `if (role==='admin')`，后端角色一改名全挂，应该全走权限码。
- 按钮权限过了，导出接口没校验，等于没做。
