# 进程与集群

## 核心回答（面试口述版，1 分钟能讲完）

Node 的 JS 跑在单线程上，要用多核就开多进程。`cluster` 让 master `fork` 出和 CPU 核数相当的 worker，master 在 Linux 上自己 `accept` 再把连接分给 worker（默认 round-robin），Windows 是共享 listen 句柄。`child_process` 三件套：`spawn` 跑任意命令走流、`exec` 走 shell 并把 stdout 攒成字符串、`fork` 专门拉 Node 子进程并带 IPC。进程间靠 `process.send` / `child.send` 传消息，也能传 socket 句柄。

## 展开

1. cluster 多进程负载均衡原理（主进程 accept 分发）

   `cluster.isPrimary` 为真时调 `cluster.fork()`。每个 worker 是独立 V8，内存不共享。
   - **round-robin（SCHED_RR）**：master 监听端口，`accept` 后把连接通过 IPC 把 fd 发给某个 worker。Linux 默认这套。
   - **共享 socket（SCHED_NONE）**：所有 worker 抢同一个 listen fd，由内核唤醒。Windows 默认。

   worker 挂了可以 `'exit'` 里再 fork。无状态 HTTP 好拆；有内存态（WebSocket 房间、本地 session）要粘滞或外置到 Redis。

2. child_process 的 spawn/exec/fork 区别

   | API | 干什么 | 输出 | 有无 IPC |
   | --- | --- | --- | --- |
   | `spawn(cmd, args, opts)` | 拉进程，不经过 shell（`shell: true` 才走） | Stream | 默认可关 |
   | `exec(cmd, cb)` | `/bin/sh -c` 跑整串命令 | 缓冲到内存，有 `maxBuffer` | 无 |
   | `execFile` | 不经过 shell 跑可执行文件 | 缓冲 | 无 |
   | `fork(modulePath)` | `spawn(process.execPath)` + IPC 通道 | Stream + `send` | 有 |

   `exec` 适合短输出命令；大日志、ffmpeg 用 `spawn`，不然 `maxBuffer` 爆。`fork` 用来跑 JS worker，和 cluster 同源。

3. 进程间通信 IPC 的方式

   - `child.send(msg)` / `process.on('message')`：libuv 的 pipe，JSON 序列化。可附 `{ cmd: 'NODE_HANDLE' }` 把 TCP server / socket 传过去，cluster 分发连接就是这个。
   - stdin/stdout 管道：`spawn` 的 `stdio: 'pipe'`。
   - 共享文件、Unix domain socket、Redis pub/sub：跨机器或不想绑父子关系时用。
   - `worker_threads` 的 `MessageChannel` / `SharedArrayBuffer` 是线程通信，别和进程 IPC 混着说。

## 代码 / 例子

```js
const cluster = require('cluster');
const http = require('http');
const os = require('os');

if (cluster.isPrimary) {
  for (let i = 0; i < os.cpus().length; i++) cluster.fork();
  cluster.on('exit', (w) => cluster.fork());
} else {
  http.createServer((req, res) => res.end('pid ' + process.pid)).listen(3000);
}
```

## 常见追问

- Q: Node 是单线程，怎么利用多核 CPU？
  A: JS 和事件循环单线程，libuv 还有默认 4 个文件线程池。多核靠多进程：`cluster` / PM2，每个进程一颗核跑自己的事件循环。CPU 密集（加密、图片、压缩）也可以丢 `worker_threads`，同进程共享内存，避免 IPC 拷贝。I/O 密集先 cluster，CPU 密集再考虑线程。
- Q: cluster 和 PM2 的关系？worker_threads 又是干嘛的？
  A: PM2 是进程管理器，cluster 模式内部就是 Node `cluster`，外加 0 停机重载、日志、监控。`worker_threads` 是同一进程里的额外 V8 isolate，能 `require` 同一份模块、能 `Atomics` 等共享内存，崩一个线程不一定崩整个进程的 fd，但 JS 堆不共享。别用线程去听 HTTP 端口，端口共享还是进程的事。

## 自己的易错点 / 之前答崩过的地方

- 在 worker 里每人 `listen(3000)` 以为会 EADDRINUSE。cluster 下是共享端口，这是正常的。
- 把 session 存在进程内存，用户下一次打到另一个 worker 就掉登录。要 Redis。
- `exec` 拼用户输入等于远程 shell，必须用 `execFile` / `spawn` 数组参数。
- 以为 `worker_threads` 能绕开单线程事件循环去 `fs.readFile` 更快。文件 I/O 本来就在线程池，再套一层没意义。
