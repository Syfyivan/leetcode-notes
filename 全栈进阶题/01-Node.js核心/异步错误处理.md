# 异步错误处理

## 核心回答（面试口述版，1 分钟能讲完）

Node 异步错误有三条路：回调约定 `fn(err, data)`，第一参非空就是失败；Promise 用 `.catch` 或 `await` + `try/catch`；谁都不接就变成 `uncaughtException` / `unhandledRejection`。async 函数里 `throw` 等于返回拒绝的 Promise，能被上层 `await` 接到。Express 的 async 路由默认不 catch，必须包一层 `next(err)`，否则客户端一直转圈，进程打拒绝警告。

## 展开

1. 回调 error-first、Promise catch、async/await try-catch 三种范式

   - **error-first**：Node 核心 API 的老约定，`fs.readFile(path, (err, data) => { if (err) ... })`。不能 throw，throw 会落到调用栈外。
   - **Promise**：`readFile(path).catch(handler)`。链中间任何一步 `throw` / `return Promise.reject` 都会跳到最近的 `catch`。
   - **async/await**：同步长相，失败走 `try/catch`。漏 await 等于丢弃 Promise，错误进 `unhandledRejection`。

   新代码用 Promise 化 API（`fs.promises`、`util.promisify`），回调风格只留在边界。

2. 未捕获异常 uncaughtException / unhandledRejection

   - `uncaughtException`：同步抛错没人接，或 EventEmitter `'error'` 没监听。Node 文档说进程已经处于不确定状态，正确做法是打日志然后 `process.exit(1)`，让 cluster / PM2 拉起新进程。继续跑可能已经脏了内存。
   - `unhandledRejection`：Promise 拒绝没 catch。Node 15 起默认把未处理拒绝改成崩溃（加 `--unhandled-rejections=strict` 同理）。监听它可以打日志，但不该当正常业务分支。

   这两类事件是最后的网，业务错误要在请求作用域里接住。

3. async 函数里抛错怎么冒泡

   `async function f() { throw e }` 等价于 `return Promise.reject(e)`。调用方 `await f()` 时，`e` 会在 await 那一行抛进调用方的 try/catch。没人 await 也没人 `.catch`，就变成 unhandledRejection。`Promise.all` 里一个拒绝整个拒绝；要收齐用 `allSettled`。

## 代码 / 例子

```js
// Express 统一包异步路由
const wrap = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get('/user/:id', wrap(async (req, res) => {
  const u = await db.find(req.params.id);
  if (!u) { const e = new Error('not found'); e.status = 404; throw e; }
  res.json(u);
}));

app.use((err, req, res, next) => {
  res.status(err.status || 500).json({ message: err.message });
});
```

## 常见追问

- Q: Promise 链里漏写 catch 会怎样？
  A: 拒绝沿链往下传，末尾没人接就是 `unhandledRejection`。Node 15+ 默认会把进程打挂。中间 `.then` 如果返回新 Promise，错误继续传；`.then(onFulfilled, onRejected)` 的第二参也能接，但后面再 throw 仍要靠后续 catch。
- Q: 怎么给 Express 的异步路由做统一错误捕获？
  A: 上面的 `wrap`，或者 `express-async-errors` 去 patch。原则：把 async handler 的拒绝转成 `next(err)`，让四参数错误中间件写状态码。Koa / Nest 自己 await handler，不用这层。别在 handler 里空 `catch` 把错误吞掉。

## 自己的易错点 / 之前答崩过的地方

- `try { getData().then(...) } catch {}` 接不住 Promise 拒绝，try/catch 只接同步和 await。
- 监听了 `uncaughtException` 还不退出，用脏进程继续接流量，问题更难查。
- Express 里 `async (req, res) => { throw err }` 不 `next`，浏览器一直 pending。
- `new Promise((resolve, reject) => { fs.readFile(..., (e, d) => { if (e) throw e }) })` 这个 throw 在回调里，Promise 接不到，应 `reject(e)`。
