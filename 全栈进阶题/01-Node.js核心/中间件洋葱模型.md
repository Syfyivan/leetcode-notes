# 中间件洋葱模型

## 核心回答（面试口述版，1 分钟能讲完）

Express 中间件是线性的：`next()` 把控制权交给下一个，`next` 后面的代码等下一个函数返回才跑，但 Express 不 `await`，所以异步中间件返回之后外层已经继续了。Koa 是洋葱：每个中间件 `await next()`，进去是从外到内，回来是从内到外，出入都能插逻辑。`compose` 把中间件数组收成一个函数，靠递归 `dispatch(i)` 串起来。错误在 Koa 里用 `try/catch` 包 `next()`，Express 靠 4 参 `(err, req, res, next)`。

## 展开

1. Express 的线性 next 和 Koa 的洋葱 await next() 区别

   Express：`fn(req, res, next)`。调用 `next()` 立刻进入下一个中间件，当前函数若在 `next()` 之后还有同步代码会马上跑，等不到后面的异步结束。响应头往往在最里层 `res.send` 时已经发出，外层很难再改 body。
   Koa：`fn(ctx, next)`。`await next()` 把「下游整条链」当成 Promise。下游 handler 跑完、甚至已经写好 `ctx.body`，控制权沿栈返回，外层还能改状态码、包一层 JSON、记耗时。这就是洋葱：进的时候日志 / 鉴权，出的时候计时 / 统一格式。

2. compose 是怎么把中间件数组串成洋葱的

   核心是 `dispatch(i)`：跑 `middleware[i]`，把 `() => dispatch(i + 1)` 当作 `next` 传进去。最后一个 `next` 解析为 `Promise.resolve()`。中间件必须 `return next()` 或 `await next()`，否则下游不会等。多次调用 `next()` 要抛错，防止链分叉。Koa 源码大约 40 行，和前端 `compose` 同一思路。

3. 错误处理中间件在两种模型里的写法

   Express：写在路由后面，签名必须四个参数 `function(err, req, res, next)`。异步路由里 `throw` 抓不到，要 `next(err)` 或包一层。
   Koa：最外层中间件 `try { await next() } catch (e) { ctx.status = 500; ctx.body = ... }`。下游任何 `await` 拒绝都会冒到这里。也可以 `app.on('error', ...)` 做日志。

## 代码 / 例子

```js
function compose(mws) {
  return function (ctx) {
    return dispatch(0);
    function dispatch(i) {
      if (i === mws.length) return Promise.resolve();
      return Promise.resolve(mws[i](ctx, () => dispatch(i + 1)));
    }
  };
}

const app = compose([
  async (ctx, next) => {
    const t = Date.now();
    await next();
    console.log(Date.now() - t, ctx.body);
  },
  async (ctx) => { ctx.body = 'ok'; },
]);
```

## 常见追问

- Q: Koa 里 await next() 之后的代码什么时候执行？
  A: 等下游所有中间件（含路由 handler）的 Promise 敲定之后。请求从外往里进，handler 写 `ctx.body`，再从里往外执行 `await next()` 后面的语句。所以计时、压缩、统一包 `{ code, data }` 都写在 `await next()` 之后。
- Q: 手写一个简易 compose？
  A: 就是上面那个 `dispatch(i)`。要点：`next` 只能调一次；`dispatch` 返回 Promise；中间件里漏 `return next()` 会提前结束。Express 没有这层 compose，它是数组下标往前推，靠 `next(err)` 跳到错误中间件。

## 自己的易错点 / 之前答崩过的地方

- 在 Express 异步 handler 里 `throw`，进程直接 `unhandledRejection`，页面一直挂着。Koa 不会，Express 会。
- Koa 中间件忘了 `await next()`，后面路由根本不跑，表现为 404。
- 把洋葱理解成「两个队列」。其实是同一条调用栈上的递归 Promise，和 `koa-compose` 源码一致。
- Express 错误中间件少写 `err` 参数，Express 不认它是 error handler。
