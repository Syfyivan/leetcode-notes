# 数据结构与应用场景

## 核心回答（面试口述版，1 分钟能讲完）

Redis 五个基本类型：String、List、Hash、Set、ZSet。另外常用 Bitmap、HyperLogLog、GEO、Stream。选类型看操作：计数和缓存用 String；对象字段局部更新用 Hash；队列用 List；去重用 Set；排行榜用 ZSet（跳表，`ZINCRBY` + `ZREVRANGE`）。小对象走紧凑编码（listpack / intset），大了才转哈希表或跳表，省指针开销。

## 展开

1. 五种基本类型 + bitmap/hyperloglog/geo

   - **String**：字节串，最大 512MB。INCR、SET EX、分布式锁 `SET NX PX`。
   - **List**：两端推弹，消息队列雏形、最新列表。Redis 5 后真队列更推荐 Stream。
   - **Hash**：field-value，商品详情、用户资料。`HINCRBY` 改单个库存字段。
   - **Set**：无序唯一。关注关系、抽奖池、`SINTER` 共同好友。
   - **ZSet**：有序唯一，score + member。排行榜、延迟队列（score=时间戳）。
   - **Bitmap**：String 上的位。签到、布隆过滤器自己实现。
   - **HyperLogLog**：基数估算，误差约 0.81%，UV 统计。
   - **GEO**：ZSet + geohash，附近的人。
   - **Stream**：radix tree，消费者组，比 List 做 MQ 靠谱。

2. 各类型的典型场景（zset 排行榜、hash 存对象）

   排行榜：`ZINCRBY rank 1 uid`，`ZREVRANGE rank 0 99 WITHSCORES`。
   购物车 / 商品：Hash，改价格不需要把整个 JSON GET/SET。
   验证码、Session、热点缓存：String + TTL。
   点赞：Set 存 uid，`SCARD` 当计数，或 String 计数 + Set 去重。
   滑动窗口限流：ZSet score=时间戳，`ZREMRANGEBYSCORE` 删过期。

3. 底层编码（ziplist/skiplist 等）

   面试常考的编码（Redis 7 名字略有变化）：
   - String：`int`（整数）/ `embstr`（短串和 SDS 一次分配）/ `raw`
   - List：`quicklist`，节点内部是 listpack（老版本 ziplist）
   - Hash：小用 `listpack`（老 `ziplist`），大用 `hashtable`
   - Set：全整数用 `intset`，否则 `hashtable`
   - ZSet：小用 `listpack`，大用 `skiplist` + `hashtable`（按 member 查 score 是 O(1)）

   转换阈值看 `hash-max-listpack-entries` 这类配置。跳表平均 O(log N) 范围查询，对缓存场景够用。

## 代码 / 例子

```text
SET session:u1 '{...}' EX 1800
HSET item:9 price 199 stock 50
ZINCRBY board 1 alice
ZREVRANGE board 0 9 WITHSCORES
PFADD uv:20240822 u1 u2 u1
BITSET sign:u1 200 1
XADD orders * sku 9 qty 1
```

## 常见追问

- Q: 为什么 zset 用跳表而不是红黑树？
  A: 跳表范围查询是顺序沿层走，好写，锁和并发改造（Redis 单线程反而无所谓）也直观。红黑树旋转复杂，插入要染色。跳表多几层指针，内存略高，Redis 用 hashtable 补了按 member 的点查。ZSet 同时要「按人查分」和「按分排范围」，skiplist + dict 这对组合刚好。
- Q: String 存 JSON 和 Hash 存对象怎么选？
  A: 整存整取、对象很小、不改内部字段：JSON String，一次网络往返。经常改单个 field、或只要几个 field：Hash，避免反复序列化。Hash 不能给单个 field 设 TTL（要等到 Redis 7.4+ 的 field 过期，老版本没有），整个 key 过期。嵌套很深的文档不适合 Hash。

## 自己的易错点 / 之前答崩过的地方

- 用 List 当 MQ 还不 ACK，消费者崩溃消息丢。至少 `RPOPLPUSH` 到处理中队列，正经场景用 Stream 的 PEL。
- 把 ZSet 的 score 当唯一键。相同 score 靠 member 字典序，member 才唯一。
- 大 Hash / 大 ZSet 做 `HGETALL` / `ZRANGE 0 -1`，单线程卡住。改扫描 `HSCAN`。
