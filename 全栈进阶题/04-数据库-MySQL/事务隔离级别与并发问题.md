# 事务隔离级别与并发问题

## 核心回答（面试口述版，1 分钟能讲完）

并发事务会撞上三类现象：脏读（读到别人未提交）、不可重复读（同一行两次结果不同）、幻读（范围里多出行或少出行）。SQL 标准四个级别：读未提交、读已提交、可重复读、串行化。MySQL InnoDB 默认 **可重复读（RR）**。RR 下快照读靠 MVCC 的 ReadView，第一次普通 SELECT 拍快照，之后同事务再读同一快照；当前读（`SELECT ... FOR UPDATE` / `UPDATE`）靠临键锁堵住间隙，避免再插入。所以「RR 有没有彻底消灭幻读」要分快照读还是当前读。

## 展开

1. 脏读/不可重复读/幻读三种问题

   - **脏读**：T2 改了还没提交，T1 读到了，T2 一滚，T1 拿到不存在的值。
   - **不可重复读**：T1 读行 A=1，T2 提交把 A 改成 2，T1 再读变成 2。针对「同一行的修改 / 删除」。
   - **幻读**：T1 按条件读到 10 行，T2 插入一行并提交，T1 再读变成 11 行。针对「范围内新插入」。

2. 四种隔离级别怎么逐级解决

   | 级别 | 脏读 | 不可重复读 | 幻读 |
   | --- | --- | --- | --- |
   | READ UNCOMMITTED | 可能 | 可能 | 可能 |
   | READ COMMITTED | 否 | 可能 | 可能 |
   | REPEATABLE READ | 否 | 否 | InnoDB 快照读下基本否 |
   | SERIALIZABLE | 否 | 否 | 否（普通 SELECT 升成加锁读） |

   RC 每条语句新 ReadView，所以能读到其他事务已提交的改动。RR 用同一个 ReadView。SERIALIZABLE 给所有读加共享锁，吞吐掉一截。

3. MySQL 默认 RR，用 MVCC + 间隙锁解决幻读

   行上有隐藏列 `DB_TRX_ID`、`DB_ROLL_PTR`。更新不原地抹掉历史，旧版本挂到 undo 链。
   快照读：根据 ReadView 的 `m_ids` / `min_trx_id` / `max_trx_id` 判断这行版本对当前事务是否可见，不可见就沿 undo 找旧版本。
   当前读：加 **临键锁** = 记录锁 + 间隙锁，间隙里别人插不进去，从锁的层面堵幻影。

## 延伸

- 相关题：锁机制。普通 SELECT 默认不加行锁，`FOR UPDATE` 才是当前读。RR 的间隙锁在 RC 下基本没有。
- 对比：不可重复读针对「同一行被改」，幻读针对「范围内新插入」。两次结果不同，先问改的是行还是集合。
- 加码：自己用两个会话走一遍「先 SELECT 再 FOR UPDATE」。比背「RR 还有没有幻读」记得住。

## 代码 / 例子

```sql
-- 会话 1，默认 RR
START TRANSACTION;
SELECT * FROM t WHERE id > 10;     -- 快照读，记下 10 行

-- 会话 2
INSERT INTO t VALUES (15, 'x'); COMMIT;

-- 会话 1
SELECT * FROM t WHERE id > 10;     -- 还是 10 行（同一 ReadView）
SELECT * FROM t WHERE id > 10 FOR UPDATE; -- 当前读，能看到 15，且给间隙加锁
```

## 常见追问

- Q: RR 级别下幻读被完全解决了吗？
  A: 快照读：同一事务普通 SELECT 看到的范围不变，插进来的行不可见，看起来没有幻读。当前读：靠间隙锁 / 临键锁阻止别人插入，也堵住了。但快照读和当前读混用仍能「看见幻影」：先普通 SELECT 10 行，别人插入提交，再 `SELECT FOR UPDATE` 变成 11 行。另外有些奇技（修改主键值等同删除+插入）也能绕。所以标准意义上的幻读在 InnoDB RR 里被压得很小，但不能说数学上绝迹。
- Q: MVCC 的 ReadView 是怎么判断可见性的？
  A: 创建 ReadView 时记下：当时还活跃的事务 ID 列表 `m_ids`，最小活跃 `min_trx_id`，下一个待分配 `max_trx_id`。行的 `trx_id`：
   - `< min_trx_id`：创建时已提交，可见
   - `>= max_trx_id`：将来的事务，不可见
   - 落在中间：在 `m_ids` 里则还活跃，不可见；不在则已经提交，可见
   自己改的行总可见。RC 每条语句拍一次 ReadView，RR 在事务里第一次快照读拍一次。

## 自己的易错点 / 之前答崩过的地方

- 把不可重复读和幻读混成「两次结果不一样」。一个是行被改，一个是行集合多了。
- 说「RR 彻底解决幻读」。面试官一问 `FOR UPDATE` 就露馅。
- 以为 MVCC 不加锁所以 UPDATE 也不锁。写一定加锁，MVCC 只管快照读。
- 在 RC 下讲间隙锁。RC 默认间隙锁很少（唯一键冲突等特例除外），RR 才普遍用 next-key。
